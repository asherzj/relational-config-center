# Web 设计规范

正式 Web 采用 **shadcn/ui + Tailwind CSS 4**。目标是让配置管理界面精致、清晰且安静：主要依靠排版、间距、对齐和操作层级组织内容。本文替代此前的青绿主题规范，是后续页面和组件的统一依据；`prototype/` 中的历史演示不作为实现标准。

## 设计方向

- 中性灰画布、白色内容面板、石墨色主按钮。当前导航使用浅灰底和较深文字，不使用彩色侧条、装饰圆点或大面积品牌色。
- 彩色仅表达业务状态：绿色表示激活、启用或允许；琥珀色表示草稿、待确认；红色表示危险、错误或删除。状态必须同时有中文文字。
- 内容先于装饰。规则名称是第一层，编码和类型是第二层，审计时间和辅助说明是第三层。不同信息使用字号、字重和间距区分。
- 面板使用细边框，页面内不堆叠阴影。阴影只用于浮层、菜单和临时反馈。规则效果采用平铺文字行，避免在面板中再嵌套三列小卡片。
- 页面说明使用任务语言，不增加不真实的环境选择器、在线状态或“连接就绪”保证。

## 颜色与尺寸

运行时值统一位于 `src/styles.css` 的 `:root`，通过 `@theme inline` 映射到 Tailwind 语义工具类。组件使用 `bg-card`、`text-muted-foreground`、`border-border` 等语义名称，不在页面内复制调色板。

| 语义 | 值 | 使用场景 |
| --- | --- | --- |
| background | `#fafafa` | 页面画布 |
| foreground / primary | `#27272a` | 主文字、主操作 |
| card / popover | `#ffffff` | 面板、抽屉、菜单 |
| muted / secondary / accent | `#f4f4f5` | 辅助表面、表头、悬停 |
| muted-foreground | `#64646e` | 标签说明、编码、审计信息 |
| border | `#e4e4e7` | 内容分隔与面板边界 |
| input / ring | `#d4d4d8` / `#71717a` | 控件边界与键盘焦点 |
| success / success-soft | `#287048` / `#edf6ef` | 激活、启用、成功 |
| warning / warning-soft | `#8b6115` / `#fbf4e4` | 草稿、无法确认能力 |
| destructive / danger-soft | `#b42335` / `#fff1f2` | 删除、错误、危险确认 |

旧布局别名（例如 `--ink`、`--line`、`--surface`）映射到以上变量，不构成另一套色彩系统。当前只提供浅色主题，不显示未经实现的主题切换。

## 组件与职责

官方组件源码保存在 `src/components/shadcn/`，配置由 `components.json` 管理，使用 `new-york`、`neutral` 和 Lucide 图标。它们是项目拥有并维护的源码，不是只仿照 shadcn 画出的 CSS。

| 组件 | 正式应用中的用途 |
| --- | --- |
| Button | 页面主操作、行内操作、表单提交与关闭 |
| Input、Textarea、Label | 筛选、规则表单、动态数据编辑、账号表单 |
| NativeSelect | 类型、排序、规则、表和字段值模式选择；保留原生选择器与表单语义 |
| Checkbox | 操作授权、新增记录的字段包含开关、NULL 值选择、范围边界 |
| Table | 三类规则目录、动态查询结果、Change Set |
| Badge | 生命周期、启用状态和环境说明 |
| Separator、DropdownMenu | 侧栏账号入口及其菜单 |
| Sheet | 规则详情、新建与编辑抽屉 |
| Dialog | 危险确认、未保存退出确认、Change Set、执行结果 |
| Skeleton、Sonner | 加载占位与成功反馈 |

`src/components/ui/` 保留业务组合：`Button` 映射现有 variant，`Drawer` 组织抽屉标题/内容/底部，`ModalSurface` 统一对话框表面，`ConfirmDialog` 处理危险动作，`ToastProvider` 提供全站反馈入口。页面不得重新实现通用输入框、按钮或弹窗外观。

表单使用 NativeSelect 是有意选择：现有规则、动态字段和自动化测试依赖原生 `option`、标签与禁用表单的行为。未来确有可搜索选项的需求时，再引入 Combobox。

## 页面布局

- **主导航**：按使用频率从上到下排列为“配置管理”（统一变更入口、发布单、通知中心）、“表配置管理”（查询规则定义、变更规则定义、表规则分配、发布流程模板，其中模板入口仅管理员可见）和“平台人员管理”（角色管理、账号角色，仅管理员可见）；顶部位置名称与当前页面所属分组一致，隐藏无权限的整组入口。
- **查询规则定义**：名称、编码和类型成组；展示查询默认值、生命周期和最近更新。类型注册信息轻量展示，主要操作为新建草稿。
- **变更规则定义**：按新增、修改、删除、自动填写字段、状态组织列；日期不拆成零碎数字，长编码可换行，操作列保持可见。
- **表规则分配**：数据库表概览采用列表行；目录将查询与变更规则成组展示。筛选输入与表格共用面板，不做重复工具栏。管理员从行内“字段配置”打开真实字段配置抽屉，按显示、查询、录入分组；静态选项以名称／实际值逐行编辑，数字范围与步长使用字符串输入，预填明确区分未配置／指定值／NULL。字段切换保留输入，保存错误定位对应字段，完整保存与停用遵循既有未保存和未知结果保护。页面细节见[字段规则管理设计](../docs/design-notes/field-policy-management.md)。
- **表发布流程设置**：管理员从表规则目录的「发布流程」进入抽屉，按常规／应急分区查看当前模板、有效状态、版本、审计及候选节点；选择器仅列出同类型模板。常规关联可停用，应急固定启用；保存失败保留选择，版本冲突可显式读取最新关联并保留输入后再次保存。表规则创建、替换、启用和停用与关联管理均通过原操作手动重推未知结果，冻结原目标、版本、内容和请求键；当前权限仍决定是否允许重推，不设置独立只读结果核对入口。原操作成功后重新读取当前配置，历史重放结果不能覆盖当前缓存；干净关联表单同步成功读取，编辑中保留原基线。确定版本冲突可核对最新后建立新意图，权限拒绝继续保留未知原包。恢复读取和写入共享忙碌保护，失败读取不能凭旧缓存清除错误。
- **发布流程模板**：管理员从目录查看同类型的多份模板，通过抽屉创建、查看和编辑受约束节点；编码和类型创建后保持稳定。应急模板的停用与删除操作不可用，常规模板的停用和删除使用共享危险确认。版本冲突保留表单输入；结果未知时冻结原动作、目标、正文、版本和请求键，只在原业务操作中手动重推，并显示 Request ID。
- **统一变更入口**：依次选择表、填写组合筛选、查看结果。组合筛选直接展示当前全部 effective 可查询字段，按 display_order 再按真实字段名排列；多列字段卡片在手机转单列，长表在筛选区局部滚动。结果列按当前字段配置的 is_visible 过滤，再按 display_order 与真实字段名排列；中文名称和静态选项名称旁始终保留真实字段名与实际值。删除确认不沿用列表隐藏规则，完整列出本次涉及的真实记录。字段配置按表批量读取，失败时结果保留原字段和值，并显示可单独重试的错误。运算符决定单值／集合／范围／无值形状，同形状切换保留输入，跨形状清空；仅一个运算符时显示名称而不展示选择器。空字符串、NULL 与未筛选分别表达，select/radio 首次未选择不得误示已选空值；查询值控件的可访问名称带“筛选”前缀，以区别同时打开的记录编辑器。折叠保留输入，清空同时重置控件内部中间态；查询与清空按钮、排序分页保持可达。字段读取失败提供错误与重试，失配显示警告与文本回退，容量超限明确阻止查询。表选择器旁提供“查看当前表规则能力”按钮，规则说明默认收起，点击后在选择器下方展开，再次点击可收起；切换表后恢复收起。按钮提供明确的展开状态并支持键盘操作。展开后的规则效果保持完整可读，按操作逐行说明自动填写行为；宽数据表在自身容器滚动。
- **规则与记录编辑**：抽屉固定标题和底部操作，内容独立滚动；相关字段成组，组之间用间距与分隔线区分。名称描述与执行规则分开。
- **记录的 NULL 值**：字段名旁使用独立标签标明“不允许 NULL”或“允许 NULL”，不将非 NULL 等同于必填。不允许 NULL 的字段不显示 NULL 选项；允许 NULL 的字段提供有边框的“设为 NULL”勾选区，选中后显示“已设为 NULL”并禁用值输入，取消后恢复先前输入。新增记录未包含的字段保持开关禁用。
- **字段录入控件**：按当前字段规则使用文本、多行、数字、布尔、日期、日期时间、下拉或单选组。默认文本保留既有多行／CR内容；粘贴换行时转多行编辑且保护原始字符。多行编辑器随内容增长到最多42dvh，超出后在控件内部纵向滚动，保留完整原值及原始CR保护，不让长文本撑满抽屉。数字使用字符串输入并精确校验范围／步长；日期时间采用日期选择器与时间文本分量，保留微秒，TIMESTAMP 明示 UTC。下拉以静态选项或自定义输入提交实际值；单选组只允许选择，旧值单独可见。字段中文名称、真实名、类型、NULL约束与必填提示在同一标题组，说明占整行，错误紧贴值控件且修改后清除旧错误；请求审阅时若校验失败，聚焦首个错误字段的可操作控件并在抽屉内滚动到该位置，修正过程中不跳到其他字段。新增预填不构成未保存修改；新增不可编辑字段不显示也不提交；修改不可编辑字段显示原值。每次打开读取配置与真实字段列表，失败显示重试；已打开表单保留当时配置、字段控件与输入，同账号恢复亦不重绘，重开采用最新配置。Schema 漂移后的修改表单先读取当前记录原值，再展示新增字段；两次读取的 Schema 不一致或记录已消失时明确报错并提供重试，不填造空字符串，不自动推进记录版本。
- **修改记录**：以原记录填充全部可编辑字段，输入框默认可编辑，不提供字段包含勾选；提交全部可编辑字段，未改动的值保持原样，保留 NULL 与空字符串的区别。主键、数据库计算列和服务器自动填写字段仍不可编辑；打开表单本身不产生未保存修改。新增记录保留字段省略语义，用于数据库默认值和自增主键。
- **Change Set**：保留字段、原值、新值的完整对比；原值浅红、新值浅绿，并配明确列标题和差异文字。使用当前字段名称和静态选项名称辅助阅读，但不按 is_visible 隐藏本次变更，真实字段名与实际值始终可核对。标题、字段对比、草稿去向、底部操作分为四区；对比表独立滚动并支持键盘横向查看。草稿去向与标题/底栏对齐，字数放在标签右侧，已有草稿入口保持内容宽度，容量说明为辅助文字；展开选择器后桌面并列、窄屏单列，错误信息紧凑换行。取消、返回编辑、保存的顺序稳定，保存为主操作。
- **发布单列表**：每行右侧提供固定的“操作”列和“查看详情”入口，窄屏横向滚动时入口保持可见；标题也可进入详情。已提交单据显示真实已通过表数。
- **发布单详情**：以发布单业务标题作为唯一主标题，状态紧邻，保留一个返回列表入口；页头右侧集中当前操作，黑色仅突出当前主操作。申请人、创建时间、变更数紧凑展示；完整单号与邻近复制按钮、版本和复制/重新准备来源进入默认收起的基本信息。人员名称旁可按需展开、复制完整 UUID；缺少姓名时显示账号短标识并保留完整查看。取消草稿放入危险样式的更多操作，继续保留确认、权限和请求恢复保护。不显示常驻重新读取按钮；读取失败时在对应错误提示中提供重试。沿用灰色画布与石墨操作，依次呈现紧凑页头、整单阶段、逐表发布流程、变更内容、回滚原因、最近历史。整单阶段紧凑显示当前状态；逐表节点严格取各表已保存实例的名称、顺序、状态、人员与时间，不从第一张表或当前模板推断；取消、拒绝、回滚不显示为四步正常完成，快速回滚不伪造审批。已回滚原单显示当前可选原因和最近修改人／时间；真实回滚执行人或管理员可打开编辑窗口补填、修正或清空，每次修改继续显示在操作历史。桌面信息与操作并列，窄屏自然换行；长标题、展开的永久 ID 和人员姓名完整换行。页面验收约定见[发布单详情紧凑布局](../docs/design-notes/release-detail-compact.md)。
- **发布单审阅**：标题统一为“变更内容”，草稿不显示单独申请切换按钮；存在实际发布结果时显示“申请内容 / 实际发布结果”切换，真实恢复执行存在时提供恢复结果。“添加变更”作为次级操作位于工具栏，进入统一变更入口并携带当前草稿。筛选名为“只显示有变化的字段”，初次默认开启、第一项展开；MODIFY 隐藏申请未提交及确定同值字段，自动填写和数据库生成说明保持可见；关闭过滤后相同值、同为 NULL、同为空字符串及未提交字段均不使用红绿底色，实际申请差异仍以原值浅红、新值浅绿显示，待生成字段保持说明与强调。完整视图区分未提交与 NULL，不推断实际发布结果。ADD/DELETE 保留全部字段。申请差异和实际 before/final 均使用每次查看时读取的当前字段名称与静态选项名称，但不按 is_visible 隐藏本次涉及字段；真实字段名与实际值始终可核对。实际结果只读取发布时持久化的 before/final，字段配置变更只改变显示，不改写历史内容，也不从当前业务行反推。字段配置缺失时回退原名原值，读取失败时保留历史并提供独立重试。每页 20 项，定位会展开目标项，分页不改变整单操作范围。字段表实际滚动容器显式提供中文名称、Tab焦点和焦点环，容器自身聚焦时可通过左右方向键查看完整对比；表内输入控件和组合快捷键保持各自行为。成功初次默认实际数据库结果，可切回申请差异或同一原单的实际恢复结果；未完结原单的快速回滚在恢复预览窗口中一次确认，原因选填，不新建回滚单；完结后不再提供回滚。历史默认最近五条倒序，可展开全部。
- **表审批角色**：管理员从表规则行内“审批角色”进入独立抽屉，角色可检索并完整分页；已选择项跨页保留，显示名称与永久 ID。空集合明确由已启用且非申请人的 ADMIN 默认审批。保存保护独立版本；冲突保留选择、先展示最新分配再明确保存；未知结果仅重推原请求，撤权禁用写入并保留内容。
- **通知中心**：默认“待我审批”，另有“我发起的、我已处理、全部审批”；视图、表名／单号／状态筛选和分页游标保存在 URL。服务端按当前身份筛选已提交发布单，每单一行，普通发布单列表继续承载草稿。列表显示真实审批进度，长标题、表名与账号 ID 换行，窄屏视图入口两列排列，表格独立滚动且右侧“查看详情”保持可见；表格容器可通过键盘聚焦和左右滚动。查看详情复用原发布单操作，返回保留原视图、筛选和分页，加载或读取失败时同样可返回。刷新保留当前页，失败显示错误并标明上次读取的结果。侧栏的个人未读入口链接“全部审批＋仅看未读”，独立显示真实未读与待审批计数；手机从导航菜单进入。列表按个人提醒标记“未读”，未读筛选与其他筛选共同保存在 URL。进入、返回和前台停留每 30 秒刷新，可手动刷新；后台及会话中断停止通知保护请求，恢复后重新读取，跨账号不沿用计数。读取失败保留最后已知列表和计数，首次失败不显示虚假的零。在前台成功展示详情后只确认该次已见通知进度，后台加载不会提前确认；已读不代表完成审批；快速返回列表后才完成的已读确认仍更新同账号的计数与列表。已读确认失败使用紧凑行内提示并保留未读，提供“重试标记已读”；刷新同一进度不自动重试，若确认时已有新变化，提示仍有未读并提供“读取最新进展”。
- **逐表审批**：提交窗口显示各表当前角色和默认原因；提交后显示冻结角色名称与身份、各表待审批／已通过／已拒绝及真实决定来源，部分通过不标记整单审批阶段完成。批准与拒绝窗口明确列出打开时确认的全部可审批表；分页不改变范围，拒绝说明整单终止。成员或状态变化引起冲突时保留原范围、版本、意见与请求，显式读取最新范围后才创建新请求。普通 VIEWER 成员可依服务端资格审批，ADMIN 没有通用审批入口；未知结果恢复保留同账号原业务动作。
- **角色管理**：审批角色列表显示名称、说明、永久 ID、成员数量和启用状态；角色抽屉维护名称、说明、启停和成员，已选人员与检索结果分别列出用户名、显示名称和永久 ID。成员选择跨检索保留；冲突显示最新内容并保留输入，未知结果只允许原请求重推。删除使用取消优先的危险确认，只有无修改且从未引用的角色可发起删除。
- **账号角色**：当前选择与身份仅显示 VIEWER、EDITOR、PUBLISHER、ADMIN；不可变历史仍完整显示当时的 APPROVER，历史含义不进入可选权限。角色版本冲突保留选择，必须查看最新角色后明确保存。
- **账号页面**：登录和注册聚焦单列表单；账号设置分为身份信息、资料、密码、会话等区块。桌面可用两列表单，手机回到单列。

## 操作、反馈与无障碍

- 一个操作区域只突出当前主操作。次操作用 outline，行内操作用 ghost；删除、弃用和放弃使用危险文字或 destructive 按钮，不能只靠颜色辨认。
- 输入框必须有可访问标签，图标按钮必须有中文名称。保留真实的 disabled、只读、必填、错误状态和键盘焦点环。
- 状态信息不可被纯装饰标签替代。未知类型、未确认规则、请求失败和提交结果不确定分别显示真实说明及可执行的下一步。
- 表单错误靠近字段；请求错误保留稳定错误码和 Request ID。成功反馈使用 Sonner，默认 3.2 秒，可手动关闭。
- 发布单请求在 IndexedDB 的同一事务提交原正文与标识后才发出；日志按账号隔离，读取失败只阻止发布写入，不阻断账号及其他只读页面。同一范围的未确认请求不能被另一个窗口覆盖；恢复另一窗口的原请求后仍保留本窗口未保存输入。仅请求处理中暂禁同单冲突写入；请求报错后仍使用原业务按钮，手动再次点击复用原键与正文，不自动写重试或提供独立结果确认入口。关闭浮层、刷新、会话恢复、撤权或一次读取未找到不清除原请求，当前角色与账号隔离继续生效。正常主单查询决定当前状态；旧请求重放结果不能覆盖后来发生的回滚或完结。已知冲突保留申请，先审阅最新状态和差异，再明确确认重建新请求。成功响应后的本地日志清理故障不表示业务失败，仍刷新当前主单并保留原键供安全重推。
- 加载使用 Skeleton 和中文状态文字；空态说明原因与下一步，不虚构记录或自动执行创建动作。
- Esc、Tab 循环、初始焦点与关闭后的焦点恢复继续由 `useModalFocus` 处理；危险确认首先聚焦取消。只有最上层弹窗响应退出，写入期间的关闭受原有业务保护控制。

### 认证中断与浮层挂载

工作区在会话失效后隐藏但保留内存草稿。业务 `SheetContent` / `DialogContent` 使用项目增加的 `inline` 参数留在所属工作区内，避免 portal 到 `body` 后绕过认证遮罩。

这两类业务浮层的 Radix Root 使用 `modal={false}`，并由 `Drawer` / `ModalSurface` 提供遮罩、`aria-modal` 和现有焦点保护；阻止 Radix 再次接管自动聚焦、Esc 和外部点击。通用组件默认仍支持标准 Portal。请勿在升级组件时直接覆盖此适配：必须通过同账号重新登录恢复草稿、隐藏抽屉键盘隔离、嵌套确认和写入中导航的真实浏览器验收。

浮层层级：顶栏 20、抽屉容器 40、普通对话框容器 60、未保存退出确认 80、会话中断界面 100。

## 响应式与动效

- 900px 以下收起侧栏，使用菜单按钮打开；关闭时从视觉和键盘路径隐藏。移动顶栏高度 62px。
- 620px 以下字段与规则效果改为单列，抽屉全宽，操作区允许换行，账号面板缩小内边距。
- 长表格局部横向滚动，最后的操作列固定在右侧。页面本身不得横向溢出；编码可以换行，正文不依赖截断才能排版。
- 动效仅用于悬停、加载和浮层进入；尊重 `prefers-reduced-motion`。不使用渐变背景、装饰动画或大面积彩色阴影。

## 维护与验收

新增组件在 `web/` 执行 `pnpm dlx shadcn@latest add <component>`，提交组件源码和锁文件。使用官方文档核对 API；升级已定制组件先比较差异，保留本仓库的认证中断、表格密度与中文可访问名称适配。

每次调整全站样式至少检查四个业务页面、登录/注册/设置、创建与查看抽屉、未保存确认、Change Set、成功/错误/空/加载状态。桌面和 390px 手机均须检查横向溢出、操作可达性和文字换行。

验证入口：`pnpm typecheck`、`pnpm test:run`、`pnpm build`，仓库根目录 `make test-browser`。真实浏览器验收使用隔离 MySQL 与账号，覆盖会话恢复、业务写入及未保存保护。验证记录见 `docs/verification/2026-09-07-shadcn-ui.md`。

## 草稿保存与管控键（#83）

表规则配置显示“并发管控键”，从真实字段添加零个、一个或多个字段；多个字段是一组组合键。不可确定值的字段显示不可选；说明未结束明细会阻止定义变更，后台错误保留选择。发布单列表提供空草稿入口，空草稿允许保存而禁用提交。

草稿编辑沿用每页 20 项，支持跨页定位、移除最后一项和键盘上移/下移。保存只提交本次增删改和必要排序，所有分页共享整单版本。占用错误同时显示表、可在新窗口打开的占用单号、当前申请人姓名或永久账号 ID，并提供错误明细定位。版本及占用冲突保留输入；明确查看最新后重建时，只合并当前窗口实际修改，不能覆盖其他窗口未触及明细。管理员沿用当前取消草稿表单填写原因，成功后历史可追溯。

### 多表发布单

主单从标题开始保存空草稿；每条明细携带真实表名。配置内容页可将不同表的选择加入同一本人草稿，分页编辑与键盘排序保持稳定明细身份，并提交整单版本。明细摘要、编辑选择和发布/恢复结果同时标明全局位置、表名、操作和记录身份；表内游标不能作为整单顺序。发布与回滚针对最多 1,000 条的全部明细，详情主单只读摘要，申请及实际结果每页从服务器读取 20 项，所有页绑定整单版本；跨页版本变化须刷新，不得混页。编辑、复制、重新准备及冲突重建需要完整申请或全局顺序时明确收集同版本页，任一页失败不采用部分结果。背景主单更新决定当前权限，但不能替换已打开编辑器的本地输入、原基线或请求日志。每表版本及刷新通知分别展示。390px 验收同时检查页面与抽屉内真实输入的边界。

常规发布详情的整单阶段取已保存状态，逐表节点按实例顺序展示，各表使用自己的模板名称与节点；实例身份、来源模板和版本、表关联版本、保存时间可展开核对。桌面节点横向排列，窄屏纵向排列，表名、节点名和人员永久 ID 完整换行。提交前审批安排保持实时读取，提交后显示冻结的表角色；部分表通过时，整单仍为待审批。

常规流程缺失时，详情列出缺失表与阻止提交的原因，并允许通过原草稿编辑器明确保存补齐；无需为触发保存而修改标题或明细。管理员修复配置后的普通读取不会补建流程。保存只补齐缺失实例，已有实例保持不变；保存请求继续使用原正文、版本、键与 IndexedDB 日志保护。
