# Web 设计规范

正式 Web 采用 **shadcn/ui + Tailwind CSS 4**。目标是让配置管理界面精致、清晰且安静：主要依靠排版、间距、对齐和操作层级组织内容。本文替代此前的青绿主题规范，是后续页面和组件的统一依据；`prototype/` 中的历史演示不作为实现标准。

## 设计方向

- 中性灰画布、白色内容面板、石墨色主按钮。当前导航使用浅灰底和较深文字，不使用彩色侧条、装饰圆点或大面积品牌色。
- 彩色仅表达业务状态：绿色表示激活、启用或允许；琥珀色表示草稿、待确认；红色表示危险、错误或删除。状态必须同时有中文文字。
- 内容先于装饰。规则名称是第一层，编码和类型是第二层，审计时间和辅助说明是第三层。不同信息使用字号、字重和间距区分。
- 面板使用细边框，页面内不堆叠阴影。阴影只用于浮层、菜单和临时反馈。规则效果采用平铺文字行，避免在面板中再嵌套三列小卡片。
- 页面说明使用任务语言，不增加不真实的环境选择器、在线状态或“连接就绪”保证。

## 颜色与尺寸

运行时值统一位于 `src/styles.css` 的 `:root`，通过 `@theme inline` 映射到 Tailwind 语义工具类。组件使用 `bg-card`、`text-muted-foreground`、`border-border` 等语义名称，不在页面内复制调色板。

| 语义 | 值 | 使用场景 |
| --- | --- | --- |
| background | `#fafafa` | 页面画布 |
| foreground / primary | `#27272a` | 主文字、主操作 |
| card / popover | `#ffffff` | 面板、抽屉、菜单 |
| muted / secondary / accent | `#f4f4f5` | 辅助表面、表头、悬停 |
| muted-foreground | `#64646e` | 标签说明、编码、审计信息 |
| border | `#e4e4e7` | 内容分隔与面板边界 |
| input / ring | `#d4d4d8` / `#71717a` | 控件边界与键盘焦点 |
| success / success-soft | `#287048` / `#edf6ef` | 激活、启用、成功 |

| destructive / danger-soft | `#b42335` / `#fff1f2` | 删除、错误、危险确认 |

旧布局别名（例如 `--ink`、`--line`、`--surface`）映射到以上变量，不构成另一套色彩系统。当前只提供浅色主题，不显示未经实现的主题切换。

## 组件与职责

官方组件源码保存在 `src/components/shadcn/`，配置由 `components.json` 管理，使用 `new-york`、`neutral` 和 Lucide 图标。它们是项目拥有并维护的源码，不是只仿照 shadcn 画出的 CSS。

| 组件 | 正式应用中的用途 |
| --- | --- |
| Button | 页面主操作、行内操作、表单提交与关闭 |
| Input、Textarea、Label | 筛选、规则表单、动态数据编辑、账号表单 |
| NativeSelect | 类型、排序、规则、表和字段值模式选择；保留原生选择器与表单语义 |
| Checkbox | 操作授权、新增记录的字段包含开关、NULL 值选择、范围边界 |
| Table | 三类规则目录、动态查询结果、Change Set |
| Badge | 生命周期、启用状态和环境说明 |
| Separator、DropdownMenu | 侧栏账号入口及其菜单 |
| Sheet | 规则详情、新建与编辑抽屉 |
| Dialog | 危险确认、未保存退出确认、Change Set、执行结果 |
| Skeleton、Sonner | 加载占位与成功反馈 |

`src/components/ui/` 保留业务组合：`Button` 映射现有 variant，`Drawer` 组织抽屉标题/内容/底部，`ModalSurface` 统一对话框表面，`ConfirmDialog` 处理危险动作，`ToastProvider` 提供全站反馈入口。页面不得重新实现通用输入框、按钮或弹窗外观。

表单使用 NativeSelect 是有意选择：现有规则、动态字段和自动化测试依赖原生 `option`、标签与禁用表单的行为。未来确有可搜索选项的需求时，再引入 Combobox。

## 页面布局

- **主导航**：按使用频率从上到下排列为“配置管理”（发布单、配置内容管理）、“表配置管理”（查询规则定义、变更规则定义、表规则分配）和“平台人员管理”（账号角色，仅管理员可见）；顶部位置名称与当前页面所属分组一致，隐藏无权限的整组入口。
- **查询规则定义**：名称、编码和类型成组；展示查询默认值、生命周期和最近更新。类型注册信息轻量展示，主要操作为新建草稿。
- **变更规则定义**：按新增、修改、删除、自动填写字段、状态组织列；日期不拆成零碎数字，长编码可换行，操作列保持可见。
- **表规则分配**：数据库表概览采用列表行；目录将查询与变更规则成组展示。筛选输入与表格共用面板，不做重复工具栏。管理员从行内“字段配置”打开真实字段配置抽屉，按显示、查询、录入分组；静态选项以名称／实际值逐行编辑，数字范围与步长使用字符串输入，预填明确区分未配置／指定值／NULL。字段切换保留输入，保存错误定位对应字段，完整保存与停用遵循既有未保存和未知结果保护。页面细节见[字段规则管理设计](../docs/design-notes/field-policy-management.md)。
- **配置内容管理**：依次选择表、填写组合筛选、查看结果。组合筛选直接展示当前全部 effective 可查询字段，按 display_order 再按真实字段名排列；多列字段卡片在手机转单列，长表在筛选区局部滚动。结果列按当前字段配置的 is_visible 过滤，再按 display_order 与真实字段名排列；中文名称和静态选项名称旁始终保留真实字段名与实际值。删除确认不沿用列表隐藏规则，完整列出本次涉及的真实记录。字段配置按表批量读取，失败时结果保留原字段和值，并显示可单独重试的错误。运算符决定单值／集合／范围／无值形状，同形状切换保留输入，跨形状清空；仅一个运算符时显示名称而不展示选择器。空字符串、NULL 与未筛选分别表达，select/radio 首次未选择不得误示已选空值；查询值控件的可访问名称带“筛选”前缀，以区别同时打开的记录编辑器。折叠保留输入，清空同时重置控件内部中间态；查询与清空按钮、排序分页保持可达。字段读取失败提供错误与重试，失配显示警告与文本回退，容量超限明确阻止查询。表选择器旁提供“查看当前表规则能力”按钮，规则说明默认收起，点击后在选择器下方展开，再次点击可收起；切换表后恢复收起。按钮提供明确的展开状态并支持键盘操作。展开后的规则效果保持完整可读，按操作逐行说明自动填写行为；宽数据表在自身容器滚动。
- **规则与记录编辑**：抽屉固定标题和底部操作，内容独立滚动；相关字段成组，组之间用间距与分隔线区分。名称描述与执行规则分开。
- **记录的 NULL 值**：字段名旁使用独立标签标明“不允许 NULL”或“允许 NULL”，不将非 NULL 等同于必填。不允许 NULL 的字段不显示 NULL 选项；允许 NULL 的字段提供有边框的“设为 NULL”勾选区，选中后显示“已设为 NULL”并禁用值输入，取消后恢复先前输入。新增记录未包含的字段保持开关禁用。
- **字段录入控件**：按当前字段规则使用文本、多行、数字、布尔、日期、日期时间、下拉或单选组。默认文本保留既有多行／CR内容；粘贴换行时转多行编辑且保护原始字符。数字使用字符串输入并精确校验范围／步长；日期时间采用日期选择器与时间文本分量，保留微秒，TIMESTAMP 明示 UTC。下拉以静态选项或自定义输入提交实际值；单选组只允许选择，旧值单独可见。字段中文名称、真实名、类型、NULL约束与必填提示在同一标题组，说明占整行，错误紧贴值控件且修改后清除旧错误。新增预填不构成未保存修改；新增不可编辑字段不显示也不提交；修改不可编辑字段显示原值。每次打开读取配置与真实字段列表，失败显示重试；已打开表单保留当时配置、字段控件与输入，同账号恢复亦不重绘，重开采用最新配置。Schema 漂移后的修改表单先读取当前记录原值，再展示新增字段；两次读取的 Schema 不一致或记录已消失时明确报错并提供重试，不填造空字符串，不自动推进记录版本。
- **修改记录**：以原记录填充全部可编辑字段，输入框默认可编辑，不提供字段包含勾选；提交全部可编辑字段，未改动的值保持原样，保留 NULL 与空字符串的区别。主键、数据库计算列和服务器自动填写字段仍不可编辑；打开表单本身不产生未保存修改。新增记录保留字段省略语义，用于数据库默认值和自增主键。
- **Change Set**：保留字段、原值、新值的完整对比；原值浅红、新值浅绿，并配明确列标题和差异文字。使用当前字段名称和静态选项名称辅助阅读，但不按 is_visible 隐藏本次变更，真实字段名与实际值始终可核对。标题、字段对比、草稿去向、底部操作分为四区；对比表独立滚动并支持键盘横向查看。草稿去向与标题/底栏对齐，字数放在标签右侧，已有草稿入口保持内容宽度，容量说明为辅助文字；展开选择器后桌面并列、窄屏单列，错误信息紧凑换行。取消、返回编辑、保存的顺序稳定，保存为主操作。
- **发布单列表**：每行右侧提供固定的“操作”列和“查看详情”入口，窄屏横向滚动时入口保持可见；标题也可进入详情。
- **发布单详情**：顶部保留返回列表链接，不显示常驻的重新读取按钮；读取失败时在对应错误提示中提供重试。沿用灰色画布与石墨操作，依次呈现四阶段、基本信息与当前操作、申请/实际结果审阅、最近历史。步骤人员与时间只取对应真实事件（准备完成取提交）；取消、拒绝、回滚不显示为四步正常完成，快速回滚不伪造审批。桌面信息与操作并列，窄屏单列；长标题、永久 ID 和人员姓名完整换行。
- **发布单审阅**：申请差异初次默认仅看变更、第一项展开；MODIFY 隐藏申请未提交及确定同值字段，自动填写和数据库生成说明保持可见；关闭过滤后完整视图仍区分未提交与 NULL，不推断实际发布结果。ADD/DELETE 保留全部字段。申请差异和实际 before/final 均使用每次查看时读取的当前字段名称与静态选项名称，但不按 is_visible 隐藏本次涉及字段；真实字段名与实际值始终可核对。实际结果只读取发布时持久化的 before/final，字段配置变更只改变显示，不改写历史内容，也不从当前业务行反推。字段配置缺失时回退原名原值，读取失败时保留历史并提供独立重试。每页 20 项，定位会展开目标项，分页不改变整单操作范围。字段表实际滚动容器显式提供中文名称、Tab焦点和焦点环，窄屏可通过左右方向键查看完整对比；其他表格默认行为不变。成功初次默认实际数据库结果，可切回申请差异或关联的实际恢复结果；历史默认最近五条倒序，可展开全部。
- **账号页面**：登录和注册聚焦单列表单；账号设置分为身份信息、资料、密码、会话等区块。桌面可用两列表单，手机回到单列。

## 操作、反馈与无障碍

- 一个操作区域只突出当前主操作。次操作用 outline，行内操作用 ghost；删除、弃用和放弃使用危险文字或 destructive 按钮，不能只靠颜色辨认。
- 输入框必须有可访问标签，图标按钮必须有中文名称。保留真实的 disabled、只读、必填、错误状态和键盘焦点环。
- 状态信息不可被纯装饰标签替代。未知类型、未确认规则、请求失败和提交结果不确定分别显示真实说明及可执行的下一步。
- 表单错误靠近字段；请求错误保留稳定错误码和 Request ID。成功反馈使用 Sonner，默认 3.2 秒，可手动关闭。
- 发布单请求发出前保存原正文与标识；处理中或结果未知时同单冲突写入禁用，关闭浮层、刷新、会话恢复和撤权不清除原请求。恢复入口继续受当前权限与账号隔离约束；明确拒绝后须先审阅最新状态和差异，再确认重建。
- 加载使用 Skeleton 和中文状态文字；空态说明原因与下一步，不虚构记录或自动执行创建动作。
- Esc、Tab 循环、初始焦点与关闭后的焦点恢复继续由 `useModalFocus` 处理；危险确认首先聚焦取消。只有最上层弹窗响应退出，写入期间的关闭受原有业务保护控制。

### 认证中断与浮层挂载

工作区在会话失效后隐藏但保留内存草稿。业务 `SheetContent` / `DialogContent` 使用项目增加的 `inline` 参数留在所属工作区内，避免 portal 到 `body` 后绕过认证遮罩。

这两类业务浮层的 Radix Root 使用 `modal={false}`，并由 `Drawer` / `ModalSurface` 提供遮罩、`aria-modal` 和现有焦点保护；阻止 Radix 再次接管自动聚焦、Esc 和外部点击。通用组件默认仍支持标准 Portal。请勿在升级组件时直接覆盖此适配：必须通过同账号重新登录恢复草稿、隐藏抽屉键盘隔离、嵌套确认和写入中导航的真实浏览器验收。

浮层层级：顶栏 20、抽屉容器 40、普通对话框容器 60、未保存退出确认 80、会话中断界面 100。

## 响应式与动效

- 900px 以下收起侧栏，使用菜单按钮打开；关闭时从视觉和键盘路径隐藏。移动顶栏高度 62px。
- 620px 以下字段与规则效果改为单列，抽屉全宽，操作区允许换行，账号面板缩小内边距。
- 长表格局部横向滚动，最后的操作列固定在右侧。页面本身不得横向溢出；编码可以换行，正文不依赖截断才能排版。
- 动效仅用于悬停、加载和浮层进入；尊重 `prefers-reduced-motion`。不使用渐变背景、装饰动画或大面积彩色阴影。

## 维护与验收

新增组件在 `web/` 执行 `pnpm dlx shadcn@latest add <component>`，提交组件源码和锁文件。使用官方文档核对 API；升级已定制组件先比较差异，保留本仓库的认证中断、表格密度与中文可访问名称适配。

每次调整全站样式至少检查四个业务页面、登录/注册/设置、创建与查看抽屉、未保存确认、Change Set、成功/错误/空/加载状态。桌面和 390px 手机均须检查横向溢出、操作可达性和文字换行。

验证入口：`pnpm typecheck`、`pnpm test:run`、`pnpm build`，仓库根目录 `make test-browser`。真实浏览器验收使用隔离 MySQL 与账号，覆盖会话恢复、业务写入及未保存保护。验证记录见 `docs/verification/2026-09-07-shadcn-ui.md`。

参考：[shadcn/ui 文档](https://ui.shadcn.com/docs)、[Tailwind CSS](https://tailwindcss.com/docs)。
