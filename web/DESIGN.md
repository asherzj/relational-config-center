# Web 视觉规范

用户在本次设计评审中明确选择：**现代轻盈，更多留白、柔和色彩、较强层次**。该方向适用于正式 Web 的四个页面及其共享表单、抽屉与反馈状态。

## 视觉语言

- 雾灰底色 `#f5f7f9`，白色内容面板，浅灰导航底色。依靠表面明度和细分隔线组织层次。
- 低饱和青绿 `#247b70` 用于主操作与当前导航；浅绿、浅琥珀和中性灰分别表达可用、草稿和弃用状态，始终配文字。
- 系统中文无衬线字体；等宽字体仅用于规则编码、字段名和数据。页面标题 25px / 600，表单与正文 13px，辅助信息 11–12px。
- 面板圆角 12px，控件圆角 8px；柔和阴影仅用于抽屉、对话框和临时反馈。保留清晰焦点环和足够对比度。
- 桌面侧栏 232px、顶部 68px。页面左右留白 32px，内容区最大宽度 1600px；区块之间留白，区块内按相关性收拢。

## 信息与操作

- 列表首先显示规则名称，编码与类型作为辅助信息。最近修改时间和修改人合并展示。
- 表规则分配将查询规则与变更规则成组展示；创建人等审计细节保留在详情。
- 列表操作列固定在右侧。窄屏允许表格局部横向滚动，页面本身不产生横向溢出。
- 数据库表概览采用列表行，在窄屏中纵向排列名称、说明和状态。
- 抽屉保留固定标题、独立滚动内容和固定操作区；用分隔与间距组织表单，避免层层嵌套面板。
- 页面说明使用任务语言；环境和连接状态必须来自实际能力，禁止用固定“就绪”或空的环境下拉制造保证。
- 空状态给出可执行的下一步。进入表规则分配仅用于导航，启用仍由用户明确操作。

## 响应式与边界

- 900px 以下收起导航，关闭时从视觉及键盘路径隐藏；620px 以下表单改为单列，抽屉操作允许换行。
- 尊重系统减少动画偏好，过渡只用于反馈和抽屉进入。
- 本次统一视觉与信息呈现；规则定义、生命周期、表规则分配和变更确认的业务约束仍由现有逻辑执行。
- 后续交互重点：选择规则时展示实际效果；记录编辑自动识别变化；未保存退出保护与对话框焦点约束。
