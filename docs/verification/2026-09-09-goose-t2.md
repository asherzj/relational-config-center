## Test-first findings

The first executable acceptance failed because baseline was unsupported. The earliest implementation exposed a one-connection-pool wait on repeated baseline; releasing the locked connection before the final status snapshot fixed it. Unconfirmed baseline registration and missing initial attempt both failed before their explicit recovery paths were implemented.

The 00002 recovery test first failed on a still-old Policy definition. Recovery now accepts each existing table only at the complete previous or target definition; original tables cannot disappear, while newly introduced tables may be absent. The two audit-column renames are atomic per table.

The historical upgrade test found that Policy contraction never wrote the descriptive Table Policy comment. Compatibility therefore ignores only descriptive **table** comments and table-level AUTO_INCREMENT counters. Column defaults, column comments, constraints and CHECK text remain part of the comparison. A real default containing ` AUTO_INCREMENT=123` exposed the inherited global replacement bug; restricting normalization to the table-options footer made the rejection test pass.

The nondefault-engine test proved Goose's own MySQL ledger DDL inherits the session default. Initialization now explicitly selects InnoDB, and status rejects a nontransactional ledger. The first combined acceptance run also found a lock deadline could expire during GET_LOCK polling after observed contention and be mislabeled as a connection error; that bounded timeout now consistently reports `migration_busy`. Three consecutive concurrency reruns passed in 28.966 seconds. Test setup errors (a foreign-key name and grants on a not-yet-existing table) were corrected before their behavior results were counted.

Spec review identified a further recovery boundary: after a confirmed baseline, a completely missing version ledger allowed the old BASELINED receipt to be reused while the recovery-count update matched zero rows. A real test first reproduced the erroneous history reconstruction. Status now marks a missing ledger with a completed receipt as incompatible; recovery additionally requires the original BASELINING state, matching target, and exactly one affected recovery row before enabling completion confirmation. The new rejection test and strengthened AC-005 snapshots passed together in 26.992 seconds. Both findings were independently rechecked and closed.
