# 规格：发布单详情交互与发布后快速回滚

状态：D-001～D-017、16 条验收要求及非目标已确认，规格发布为 [GitHub #59](https://github.com/asherzj/relational-config-center/issues/59)。#60～#64 均已独立验证、评审、提交、推送，完成 Notion 项目记录更新并关闭；全部验收证据见[验收索引](../../verification/2026-09-09-release-detail-acceptance-index.md)。实现已整合到 codex/new-feature-20260908，父规格保持打开。

## 问题陈述

需求提出时，详情难以快速辨认阶段、审阅变化和执行下一步；普通发布成功即释放目标，缺少可由发布人员直接恢复的待完结阶段。以下规格描述本次已交付的改进。

## 解决方案

保持全站视觉，按阶段、身份和动作、变更审阅、操作历史组织详情。普通发布成功后持续保护目标，由当前发布人员快速回滚或明确完结。重新准备以共同成功/失败的方式取消旧审批单并生成新草稿。

## 用户故事

1. 作为查看者，我想从详情页识别当前准备、审批、发布和完结阶段，以便快速判断进展。

2. 作为编辑者，我想为新草稿设置预填且可编辑的标题，以便表达本次配置变更目的。

3. 作为编辑者，我想在批量删除、逐条保存及已有草稿入口保留正确标题，以便避免单据含义丢失。

4. 作为审批人，我想看到冻结后的标题及申请差异，以便审阅被批准的准确意图。

5. 作为查看者，我想看到人员当前姓名并可查看永久账号 ID，以便兼顾易读和归属准确。

6. 作为发布者，我想成功发布后保持待完结，以便保留快速恢复机会。

7. 作为发布者，我想在待完结期间继续保护全部目标记录，以便避免其他单修改相同记录。

8. 作为编辑者，我想在同表提交不重叠的记录，以便不被无关发布单阻塞。

9. 作为有发布权限的其他用户，我想快速回滚或完结已发布普通单，以便按当前职责处理后续操作。

10. 作为发布者，我想核对真实恢复差异并填写原因后快速回滚，以便明确恢复范围并留痕。

11. 作为发布者，我想无需新审批即可恢复待完结发布，以便及时处理不合适的配置。

12. 作为发布者，我想知道回滚因较新数据、规则或表结构失败，以便避免覆盖后来的配置。

13. 作为发布者，我想明确确认完结，以便关闭快速回滚并释放目标。

14. 作为编辑者，我想在完结后申请需要独立审批的普通回滚，以便仍能受控恢复配置。

15. 作为查看者，我想看到回滚后的原单与结果记录均已结束，以便避免误认为还可连续反向操作。

16. 作为原申请人或管理员，我想重新准备未发布的已批准普通单，以便修改意图并重新提交审批。

17. 作为管理员，我想成为自己重新准备的新草稿申请人，以便留下实际身份并维持不可自批规则。

18. 作为申请人，我想重新准备失败时保留原审批和占用，以便避免丢失可执行的原单。

19. 作为查看者，我想默认只看变化并展开第一项，以便快速审阅重要差异。

20. 作为查看者，我想区分 NULL、空字符串、未提交和生成值，以便准确理解配置内容。

21. 作为查看者，我想分页浏览最多一千项且操作始终针对整单，以便兼顾可读性和完整性。

22. 作为查看者，我想成功后默认看实际发布结果并能切换申请差异及回滚结果，以便区分意图和实际生效值。

23. 作为查看者，我想看最近五条历史并能展开全部及跳转关联单，以便追溯完整过程。

24. 作为手机及键盘用户，我想完成查看、确认、复制和关联跳转，以便不受布局或输入方式限制。

25. 作为操作人，我想在响应丢失后用原请求恢复结果，以便避免重复执行。

26. 作为操作人，我想在权限或状态变化时保留输入并明确重建，以便避免自动覆盖新的状态。

## 验收用例

沿用已确认的主验收接缝：已认证 Admin 公开 HTTP API 的单据、动作和配置查询。真实浏览器用于必须可见的交互及接线；不新增测试专用业务入口。AC 编号属于本规格。

### AC-001

- **Given**：普通单已获批准且涉及若干记录。

- **When**：执行发布后，其他单分别提交重叠和不重叠记录。

- **Then**：原单保持已发布待完结；重叠提交被拒绝，不重叠提交正常。

- **证据**：真实 MySQL 的公开 API 发布与再次提交。

- **层级**：契约/集成。

### AC-002

- **Given**：发布包含省略自增 ID 的新增及删除。

- **When**：发布成功后针对真实新增 ID 或删除 ID 提交另一单。

- **Then**：两类真实记录身份均继续受保护，完结或成功回滚才释放。

- **证据**：真实自增、删除重建及目标冲突流程。

- **层级**：契约/集成。

### AC-003

- **Given**：另一位用户拥有当前发布权限，另有仅查看/编辑/审批用户。

- **When**：分别尝试完结与快速回滚。

- **Then**：有发布权限者可执行；其余用户被拒绝，不限定原执行人。

- **证据**：公开 HTTP 权限矩阵与当前会话角色变化。

- **层级**：契约/集成。

### AC-004

- **Given**：普通单成功发布且待完结，恢复差异仍有效。

- **When**：有发布权限者确认快速回滚。

- **Then**：无需新审批整单恢复；保存真实执行人、结果和原因，原单已回滚且目标释放。

- **证据**：真实 MySQL 混合变更回滚、结果读取和历史检查。

- **层级**：契约/集成。

### AC-005

- **Given**：待回滚某项数据、规则、表结构或恢复约束已失效。

- **When**：尝试快速回滚。

- **Then**：明确失败且整单不生效；原状态、业务值、版本及占用不出现部分结果。

- **证据**：故障注入和变更后公开结果查询。

- **层级**：契约/集成。

### AC-006

- **Given**：同一版本同时收到回滚/完结或两次回滚，或成功响应丢失。

- **When**：竞争执行并用相同请求标识重试。

- **Then**：至多一个有效结果；原请求返回原业务结果，不重复恢复。

- **证据**：真实事务竞争、响应丢失后原键重放。

- **层级**：契约/集成。

### AC-007

- **Given**：普通单成功发布且待完结。

- **When**：确认完结后再申请普通审批回滚。

- **Then**：完结只关闭快速回滚及释放目标，不改业务值或冒充分发；后续回滚仍需审批，原单不重新打开。

- **证据**：完结前后配置查询及普通回滚申请流程。

- **层级**：契约/集成。

### AC-008

- **Given**：普通审批回滚已获他人批准。

- **When**：执行反向发布。

- **Then**：原单已回滚，反向结果直接结束并释放目标，无新待完结或连续反向入口。

- **证据**：完整普通回滚流程及后续动作拒绝。

- **层级**：契约/集成。

### AC-009

- **Given**：普通单已批准且未发布。

- **When**：合法原申请人或 ADMIN 重新准备，或无权者/故障/重试介入。

- **Then**：成功时旧单取消且创建同一可恢复新草稿；新申请人为实际操作者且不可自批；明确失败保留原审批与占用。

- **证据**：真实事务失败、权限与原键恢复；浏览器重新准备主路径。

- **层级**：契约/集成。

### AC-010

- **Given**：从任意创建入口保存草稿或编辑现有草稿。

- **When**：提交空、超过 100 Unicode 字符、合法或过期版本的标题，然后提交审批。

- **Then**：所有入口预填并保存合法标题；无效输入拒绝；旧版本不覆盖标题或明细；提交后冻结。

- **证据**：公开契约和草稿入口定向交互；Unicode 边界规则。

- **层级**：契约/集成。

### AC-011

- **Given**：普通查看者读取包含申请/审批/执行人员的单据，账号之后改名。

- **When**：读取详情及相关人员。

- **Then**：显示当前姓名且历史仍归永久 ID；无法解析时 ID 兜底，不需要账号管理权限。

- **证据**：公开人员读取与改名归属；展示组件交互。

- **层级**：契约/集成。

### AC-012

- **Given**：差异包含 NULL、空字符串、未提交、自动生成及最多千项混合操作。

- **When**：切换仅看变更、展开条目、分页或定位。

- **Then**：MODIFY 隐藏确定不变字段，生成说明仍可见；ADD/DELETE 完整可读；操作范围仍是整单。

- **证据**：差异组件语义/分页模块验收。

- **层级**：模块验收。

### AC-013

- **Given**：单据存在申请、实际发布及可能的回滚结果。

- **When**：打开成功或已回滚详情并切换结果。

- **Then**：默认展示可信实际结果；申请值、原发布结果和恢复结果明确区分；生成字段不由申请内容推测。

- **证据**：实际结果契约及页面切换定向验证。

- **层级**：模块验收。

### AC-014

- **Given**：发布单处于任一合法状态且历史超过五条，含长标题/ID/值。

- **When**：通过桌面、窄屏或键盘查看并操作页面。

- **Then**：阶段和动作真实，终止不伪装四步成功；默认最近五条可展开全部，关联跳转和复制反馈有效，页面无整体横向溢出。

- **证据**：页面状态测试和桌面/390px 真实浏览器检查。

- **层级**：系统关键路径。

### AC-015

- **Given**：发布者可快速回滚或完结。

- **When**：打开确认并取消，或审阅恢复差异填写原因后确认。

- **Then**：快速回滚必须先有恢复预览和原因；完结说明释放目标及关闭快速回滚；取消确认无业务变化。

- **证据**：动作组件确认门槛及真实浏览器发布→恢复/完结路径。

- **层级**：系统关键路径。

### AC-016

- **Given**：写请求正在处理或结果未知，页面刷新、恢复会话或权限变化。

- **When**：重复点击、切换终止动作或恢复原申请。

- **Then**：保留原内容与请求标识，阻止本页面冲突动作；后端竞争仍至多一个结果；明确拒绝经最新审阅才重建，不提前显示终止或释放。

- **证据**：请求日志/会话交互与真实并发验收共同证明。

- **层级**：系统关键路径。

## 故障与一致性决策

- 发布/回滚的业务值、版本、结果、目标占用、历史及成功请求结果共同提交。失败不留下部分结果。
- 重新准备的旧单取消、新草稿及身份来源、占用释放、历史和请求结果共同成功或失败。
- 网络超时或响应无法读取只表示结果未知，保留原请求标识及内容；只有明确拒绝后才可核对最新状态重建。
- 同一所见版本的竞争终止动作至多一个成功；当前权限由服务端验证，界面不是授权边界。
- 恢复只使用可信实际发布前值，拒绝较新记录、规则或结构变化及恢复值不匹配。
- 本期不投递分发通知，不设计下游故障补偿、自动倒计时或外部审批故障。

## 实现决策

- 普通 SUCCEEDED 表示已发布待完结，COMPLETED 为人工完结普通单或成功的反向结果；原单成功回滚为 ROLLED_BACK。
- 完结及快速回滚仅对待完结普通单开放，当前 PUBLISHER/ADMIN 可操作。普通回滚只对已完结普通单开放且仍需独立审批。
- 发布结果中的真实新增 ID 和删除身份持续受保护；同表不重叠记录可继续发布。快速回滚在同一事务中使用原单的目标占用。
- 新公开动作包括完结、快速回滚预览/执行、重新准备；沿用稳定请求标识、所见版本、会话和 CSRF。快速回滚预览摘要绑定当前恢复意图与执行规则。
- 标题为必填、最多 100 Unicode 字符，预填“表名 配置变更”，草稿可改、提交后冻结；普通回滚标题由原单派生。
- 本单相关人员通过只读展示接口解析当前姓名，永久 ID 保留归属与兜底。
- 重新准备只允许当前有 EDITOR 权限的原申请人或 ADMIN，新草稿归实际操作者。
- 使用真实 32 位十六进制单号及英文字段名。差异默认仅看变更、第一项展开、每页 20 项；历史默认最近 5 条倒序。
- 发布成功默认显示真实结果，可切换申请差异；已回滚可查看恢复及原发布结果。
- 快速回滚要求恢复差异、必填原因和明确确认；完结确认说明释放占用、关闭快速回滚，不强制意见。
- 保留 JSON 文档存储；标题和新状态不改变控制表的必要列，不增加无意义迁移。

## 测试决策

- 每张功能工单同时交付其公开行为和独立验证，不把测试留给最后一张水平工单。
- 真实 MySQL 的公开请求验证事务、占用、身份、并发及幂等；复用现有账号和发布单集成先例。
- 差异状态、Unicode 标题、分页、确认和请求恢复使用针对性模块/界面检查，避免各层复制相同断言。
- 一条真实多账号浏览器路径证明创建标题→独立审批→发布待完结→恢复预览→快速回滚；另覆盖重新准备及完结后普通回滚入口。
- 全部变更通过 Go/Web 类型、构建及相关回归；最终联调只补跨工单事实，不代替各工单证据。

## 临时结构与退出条件

无。不增加旧发布单兼容、双写、Feature Flag 或临时成功结果；已有未验证的中间实现须在各功能收尾。

## 上下文影响

更新 Admin 的标题、重新准备、完结、快速回滚及活动目标含义；落实 ADR-0023 对 ADR-0019/0020/0022 的相关覆盖；同步公开接口、错误及操作说明。功能通过验收后更新 Notion 项目记录。

## 超出范围

旧发布单数据兼容或清理；全站视觉改版；自定义字段显示名；截图示例编号；自动完结倒计时；连续反向发布；分发接入和新增通知渠道。没有旧发布单不代表可删除账号、规则或业务配置。
