# T5：发布全过程的结果提醒

状态：用户已确认拆分，ready-for-agent。

## 父工单

Part of #92：https://github.com/asherzj/relational-config-center/issues/92

## 要构建什么

申请人与真实参与审批的人在发布、完结和回滚后收到对应结果提醒，可直接查看原发布单真实结果。重新准备取消源单也按取消事件通知申请人，响应异常后安全重推不会重复变更或提醒。

## 验收标准

- [ ] 发布、完结、回滚只在对应真实业务结果成功时生成提醒；收件人为申请人和曾参与审批的人，排除本次操作者自身，不因其后来撤权丢失历史参与关系。
- [ ] 重新准备取消源单、创建替代草稿及旧单取消通知共同成功或失败；新草稿尚未提交时不伪造待审批提醒。
- [ ] 同单提醒持续聚合，点击可查看真实审批、发布、完结或回滚结果，不能把下游刷新通知当成人员消息或消费者已接收。
- [ ] 正式执行路径将业务数据、状态、实际结果、版本、通知和请求结果一致提交；通知失败不产生已发布但无结果提醒的部分成功。
- [ ] 对接 #86 最终错误/重推流程：原操作重推、同键异内容拒绝、当前授权、无自动重试与无独立确认入口。
- [ ] 发布/回滚与完结竞争、通知保存故障、约束失败及提交后丢响应均不产生重复成功事实或通知。

## 验收用例

唯一主要交付：AC-019、AC-020。

## 验证证据

真实 MySQL 多表生命周期和 HTTP 验证收件人及结果原子性；在通知写失败、业务约束失败、响应丢失及竞争下核对业务行、真实执行结果、状态和可读通知。浏览器证明结果跳转、重新准备和原操作重推，已有下游刷新通知记录做必要回归。

## 临时结构与退出条件

无。只接入多表功能的正式原单生命周期和共享结果，不新增独立回滚通知模型、旧确认流程或复制执行器。
