# T1：管理员维护审批角色和成员

状态：用户已确认拆分，ready-for-agent。

## 父工单

Part of #92：https://github.com/asherzj/relational-config-center/issues/92

## 要构建什么

管理员在正式角色管理页面新建和维护自定义审批角色，为角色选择多个本地账号，一个账号可以加入多个角色。保存、刷新和重新登录后可读取同一关系，普通账号无法修改，失败保留输入。

## 验收标准

- [ ] 角色有稳定身份、名称、说明、启用状态及可检索的真实成员；创建/更新/成员增删/启停/从未引用角色删除均经管理员能力执行。
- [ ] 多对多关系持久保存，重复成员不产生重复记录；角色成员身份不依赖显示名称，也不附带编辑、发布或管理员权限。
- [ ] 管理 API 校验真实身份、当前授权、请求幂等及版本；并发修改拒绝覆盖，失败和认证中断保留表单内容，同键异内容拒绝。
- [ ] 正式 Web 支持角色列表、人员选择、编辑与保存，桌面/390px/键盘基本路径可用，加载/空/错误真实。
- [ ] 新控制表采用 Goose 正式迁移和当前就绪/控制表保护约定；本张测试证明自身新增结构可安装/升级，不将全部迁移检查推迟到 T6。
- [ ] 角色删除约束为“从未引用”；为 T2 接入表绑定和审批引用提供真实持久职责，不使用测试专用接口或授权空实现。

## 验收用例

唯一主要交付：AC-001、AC-002。完整 Given/When/Then 采用父规格。引用后的生命周期保护在 T2 的 AC-003 完整证明，本张仍验证无引用角色的基础维护行为。

## 验证证据

公开 HTTP＋真实 MySQL 证明关系持久化、授权、版本与幂等。真实浏览器证明人员选择、保存、刷新和输入保护；必要客户端状态测试补认证中断及迟到响应，不重复数据库断言。

## 临时结构与退出条件

无。不双写旧固定账号角色，不改变旧审批权限或假称表审批已经接通。角色管理作为独立切片可演示，完整角色审批功能仍按父规格收尾。
