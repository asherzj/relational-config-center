# 按表审批与通知中心：交付工单拆分

状态：用户于 2026-09-11 确认规格、验收和六张工单拆分，父规格 #92、子工单 #93～#98 及原生关系均已发布并读回核对。

## 验收与设计基准

以[规格](./spec.md) AC-001～AC-023 为唯一编号来源，主要从正式 Web 验收，以公开 Admin HTTP 和真实 MySQL 独立证明权限、事务、并发及升级。沿用规格引用的 Web 设计基准，桌面/390px/键盘必须有真实浏览器证据。

每张工单都有自己的完整行为和验证；最后一张不替代前五张的测试。AC-003 中管理员的基础停用/删除入口可由 T1 实现，但有真实表绑定、审批快照及历史后的最终引用保护由 T2 唯一负责证明。

## 临时结构账本

| 结构 | 允许用途 | 引入责任 | 删除责任 | 退出证据 |
| --- | --- | --- | --- | --- |
| 旧 APPROVER 账号存储值的当前身份只读转换（仅在必要时） | 在实际审批已切换后，暂时读取尚未迁移的账号；旧值始终不授予审批权 | T2 | T6 | 正式升级后当前身份及新授权不再依赖转换，旧授权入口和有效权限已退出 |

不可变授权历史的旧角色名称解释有永久职责，不属于应删除的授权兼容；保留历史不允许旧权限重新参与当前鉴权。T1～T5 若新增任何临时结构，必须同时更新其工单及本账本，并由 T6 承担明确退出；不允许自行扩大完成定义。

## 执行与完成规则

- 用户只要求隔离工作，不要求并行；默认按前沿串行，一张工单一个独立分支/可写 worktree、验证、评审和交付周期。继续遵守 `flow-feature` / `implement`，不复制其他功能工单中的模型或推送偏好作为本会话授权。
- 本功能分支从 main 创建。每张开始前读取父规格、完整工单和评论、依赖交付及最新领域/设计/架构文档；不要基于上一张工单的残留上下文开始新张。
- 按当前 flow-feature，以新的独立 subagent 处理下一张可执行工单，仅交接必要的工单、决策、依赖提交、证据和隔离工作树信息。默认串行；主协调者核对交付后继续派发，不要求用户因切换工单另开任务。不能跳过依赖或代做其他功能工单。
- 单张功能切片完成适用检查并记录证据，完整功能需全部 AC 对应证据、临时结构退出、文档同步及 Notion 更新。不得将规格发布或工单创建报告成实现完成。
- 不直接推送或合并 main，不自动部署，不关闭或改写其他父规格。
