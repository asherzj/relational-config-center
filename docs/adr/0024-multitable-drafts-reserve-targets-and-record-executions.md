# 多表发布单从草稿保护目标，并以独立执行记录保留真实结果

用户确认一张发布单可以组织同一受管数据源内的多表有序变更，并在保存草稿明细时保护目标，以减少准备阶段的冲突。主键保护之外，表规则可以指定零组或一组并发管控键，新增保护新值、修改旧新值、删除旧值；整单版本负责同单编辑冲突，目标占用负责跨单冲突。任何未结束单的明细引用该表，就禁止改变管控键定义；这比只在提交审批时抢占目标更早建立保护，代价是遗留草稿会持续占用，需通过人工取消而非自动过期释放。

发布单、变更明细和成功执行记录各自保存流程、逐项意图及实际结果、整单执行摘要，不创建独立回滚发布单或执行结果明细表。多表正向发布与逆向回滚共用执行器，按审批冻结的顺序正向执行、倒序恢复；业务数据、各表/记录版本、真实结果、通知、主单状态和占用在整单一个事务中提交，不拆分为多个发布事务。相比独立回滚单和整单JSON结果，这减少单据与重复数据，但要求命令和通知能区分同一主单的发布与回滚两次执行。

应急回滚仅限已发布未完结原单，当前发布人员预览后一次确认，无新审批或必填原因；成功后原单已回滚并释放占用。完结后禁止回滚，原因可由回滚执行人或管理员事后选填并留痕。此项取代ADR-0020及ADR-0023中完结后新建审批回滚单和独立反向结果单的规则；保留正向独立审批、实际数据一致性检查和ADR-0022的真实结果原子性。前端请求异常只报错，不自动重试或增加独立确认流程，用户重推原操作由后端事务和幂等保证不会重复生效。

完整确认范围见[规格 #81](https://github.com/asherzj/relational-config-center/issues/81)，含整单1000条、管控键数据库等价语义和NULL处理、不支持动态引用尚未生成的ID、不做旧单数据兼容。本ADR记录完整目标决策。#82 首先在现有单表路径实现三类存储、同执行器倒序回滚、原单保留两次成功执行，以及完结后禁止回滚；多表、草稿占用与最终交互仍由后续工单推进。
