# 以稳定模板配置受约束的发布流程

管理员需要为同一种发布方式维护多份可复用流程，而后续发布单必须能够引用一个稳定定义。发布方式因此只描述共享流程类别，模板编码才标识具体模板：`STANDARD` 和 `EMERGENCY` 都允许多份模板，模板编码全局唯一且带版本，创建后编码和发布方式不变。模板名称、描述和节点名称可通过记录版本并发保护修改，创建和所有生命周期写入使用持久请求结果支持原请求重推。

模板直接保存有序的发布节点定义 JSON，不拆分第三张配置表。常规模板固定为按表审批、发布、完结，应急模板固定为发布、完结；节点编码在模板内唯一，节点能力、顺序及所需角色由发布方式约束。模板级监控列表当前固定为空，未引入监控节点配置。模板目录阶段仅声明按表审批能力；流程实例沿用正式表审批，不引入旧全局 APPROVER 授权。

应急模板始终可用，不能停用或删除，非法修改在写入前拒绝；服务就绪要求稳定编码 `default_emergency_v1` 的默认应急模板保持有效，同类型仍可存在多份模板。常规模板可以停用或删除，不构成就绪故障。模板管理的读取和写入均要求当前 ADMIN，审计保存永久 Account ID。早期 #101 切片只交付模板目录、管理 API、正式 Web 表单和第一张模板定义表；模板与表规则的关联、发布单实例化及节点执行随后由 #102～#105 接入。

完整范围见[父规格 #100](https://github.com/asherzj/relational-config-center/issues/100)与[T1 #101](https://github.com/asherzj/relational-config-center/issues/101)。

#102 增加第二张配置表，以表规则永久身份、发布方式和模板永久身份保存唯一关联；数据库复合外键保护类型一致与引用完整性，关联通过版本原子替换。既有规则初始化只补缺失关联，不覆盖管理员选择。新建表规则在同一事务创建默认应急关联，启用时确认或补齐有效应急关联；整张表规则仍可停用，常规关联可停用。应急可用性是配置不变量，数据库读取失败不会变成临时默认流程。

表规则创建、替换、启用和停用也采用持久原请求结果与可观察版本。这取代 ADR-0005 中表规则「不提供乐观锁、最后写入者获胜」的约定；两类规则一起校验替换、实时 Schema 校验与在途并发管控键保护保持原语义。当前 ADMIN 校验先于结果重推，原请求身份及正文与业务变更同事务保存，响应丢失由用户原操作手动重推。早期 #102 切片只交付配置关联与管理，实例化及常规／应急执行随后由 #103～#105 接入。

常规多表草稿在显式保存时，为新参与或尚缺流程的表持久化独立实例。每份实例保留来源模板、关联版本和完整有序节点；同表普通编辑保留已有实例，移除最后一条明细时移除该表当前实例，再次加入按当前配置生成。复制和重新准备为新单重新实例化。选择在展示前保存，是为了让用户已审阅的流程不随共享模板编辑、停用或关联切换而变化；详情读取及提交都不补建或替换实例。明确缺少常规配置的草稿可以保存，提交要求逐表实例完整；管理员修复配置后，由用户再次保存仅补齐缺失实例。

流程节点与审批分配具有不同的固定时点：前者随草稿保存，后者仍按 ADR-0026 在提交时固定表角色身份，成员资格实时校验。节点进度随真实表决定和整单发布、完结、拒绝、取消或快速回滚事实保存，不因当前人员配置或前端展示重新推断完成。实例位于现有发布单主单文档中，与内容、版本、占用、历史和原请求结果同事务保存；模板及关联通过同一草稿事务的一致读取获取，本阶段不新增配置表或 Schema 迁移。快速回滚停止尚未完成的正向节点，保留已完成的正向事实。正向接口接受常规与应急；缺配置不得回退到固定流程。

正向草稿明确改选发布方式时，才将所有参与表的节点实例与草稿变更整体重新保存；相同方式的普通编辑仍保留已有实例。应急提交保存必填原因并进入真实待发布 `PENDING_PUBLICATION`，不冻结审批责任或制造批准事实。发布资格按发布方式分别验证：常规需要各表真实批准，应急需要有效已保存流程及提交原因；两者均要求当前 PUBLISHER，申请人有该权限可自行执行。执行复用整单一次事务，成功保留占用并等待人工完结，完结释放占用且不再允许回滚。新的待发布状态也适用取消和重新准备；新草稿重新实例化、重新提交，不继承已提交原因。

原单恢复预览也采用展示前显式保存：在仍待完结的原单中实例化每表当前应急模板，首次保存推进整单版本并留下真实预览历史，后续打开复用同一实例。完整预览原请求结果与节点、版本一起持久化，代价是预览成为需要版本和请求键保护的写操作；这让丢响应后能够原样重推，并防止模板后改替换已经审阅的流程。业务当前值仍在实际逆向执行时检查，实例不延长回滚期限。成功恢复直接令原单已回滚并释放占用，发布节点记录真实回滚执行，模板中的完结节点停止，不补造审批或人工完结。权限在事务取得授权锁后重新读取，预览和执行重放也适用当前权限。

最终结构采用连续 Goose 00001～00011，保留外部已交付 1～9，模板与关联固定为 10/11；不再保留候选编号、固定流程总览或执行兜底。当前所有阶段都读取已保存实例及真实业务事实，取消、拒绝和回滚不被展示为普通完结。
