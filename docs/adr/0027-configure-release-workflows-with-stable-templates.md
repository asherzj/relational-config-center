# 以稳定模板配置受约束的发布流程

管理员需要为同一种发布方式维护多份可复用流程，而后续发布单必须能够引用一个稳定定义。发布方式因此只描述共享流程类别，模板编码才标识具体模板：`STANDARD` 和 `EMERGENCY` 都允许多份模板，模板编码全局唯一且带版本，创建后编码和发布方式不变。模板名称、描述和节点名称可通过记录版本并发保护修改，创建和所有生命周期写入使用持久请求结果支持原请求重推。

模板直接保存有序的发布节点定义 JSON，不拆分第三张配置表。常规模板固定为按表审批、发布、完结，应急模板固定为发布、完结；节点编码在模板内唯一，节点能力、顺序及所需角色由发布方式约束。模板级监控列表当前固定为空，未引入监控节点配置。审批节点只声明后续复用按表审批能力，本切片不改变现有发布单审批或执行路径。

应急模板始终可用，不能停用或删除，非法修改在写入前拒绝；服务就绪要求稳定编码 `default_emergency_v1` 的默认应急模板保持有效，同类型仍可存在多份模板。常规模板可以停用或删除，不构成就绪故障。所有读取和写入均要求当前 ADMIN，审计保存永久 Account ID。#101 只交付模板目录、管理 API、正式 Web 表单和第一张模板定义表；模板与表规则的关联、发布单实例化及节点执行由后续工单接入。

完整范围见[父规格 #100](https://github.com/asherzj/relational-config-center/issues/100)与[T1 #101](https://github.com/asherzj/relational-config-center/issues/101)。

#102 增加第二张配置表，以表规则永久身份、发布方式和模板永久身份保存唯一关联；数据库复合外键保护类型一致与引用完整性，关联通过版本原子替换。既有规则初始化只补缺失关联，不覆盖管理员选择。新建表规则在同一事务创建默认应急关联，启用时确认或补齐有效应急关联；整张表规则仍可停用，常规关联可停用。应急可用性是配置不变量，数据库读取失败不会变成临时默认流程。

表规则创建、替换、启用和停用也采用持久原请求结果与可观察版本。这取代 ADR-0005 中表规则「不提供乐观锁、最后写入者获胜」的约定；两类规则一起校验替换、实时 Schema 校验与在途并发管控键保护保持原语义。当前 ADMIN 校验先于结果重推，原请求身份及正文与业务变更同事务保存，响应丢失由用户原操作手动重推。#102 只交付配置关联与管理，实例化及常规／应急执行仍由后续工单接入。
