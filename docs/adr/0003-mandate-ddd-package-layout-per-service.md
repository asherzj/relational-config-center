# Mandate the same DDD package layout inside every service

Admin, Server, and Client each keep their own domain model and never import another service's domain packages. Within each service the four-layer layout is mandatory, Admin's being canonical: `internal/interfaces/http` (Gin handlers, HTTP DTOs), `internal/application` (query, write, and policy-management use cases), `internal/domain` (table policies, Query Specifications, validation, repository interfaces), and `internal/infrastructure/mysql` (GORM repository, MySQL query compiler). Dependencies point `interfaces → application → domain` and `infrastructure → domain` only. The existing Admin packages (`httpapi`, `managedtable`, `mysqlstore`, `bootstrap`) predate this decision; nothing is deployed, so they are deleted or rewritten to fit rather than preserved.
