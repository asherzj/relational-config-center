# 前端设计文档

## 阅读入口

- 设计、实现、评审或验收正式 Web 页面、组件、样式和交互前，先读取 [web/DESIGN.md](../../web/DESIGN.md)，再查看相关页面、组件及 [web/src/styles.css](../../web/src/styles.css) 中的实际定义。
- 页面或功能已有设计说明时，读取 [docs/design-notes/](../design-notes/) 中与当前工作有关的文档及对应规格、工单，区分待讨论方案和已确认决策。纯后端工作不要求加载前端设计文档。
- 本仓库沿用 `web/DESIGN.md`，不另建根目录或不同大小写的同名副本。文档缺失时，从现有实现与已确认设计恢复最小基准，未确认部分标为草案；缺失本身不代表需要重新选择视觉方向。

## 文档分工

- `CONTEXT.md` 与各上下文词汇表记录业务概念的含义，`CONTEXT-MAP.md` 记录上下文及其关系；阅读与维护见[领域文档约定](domain.md)。
- `web/DESIGN.md` 记录正式 Web 的共享设计方向、颜色与排版、布局、组件职责、交互、响应式及可访问性规范。
- `docs/design-notes/` 记录具体页面或功能的任务路径、状态、方案讨论和规划。可复用且已确认的规则进入 `web/DESIGN.md`，页面专属细节保留在设计说明中并按需从基准文档引用。
- ADR 记录难以回退的领域或架构决策。设计方案涉及业务语义或架构变化时，同步相关领域文档与 ADR；视觉方案不能自行改变这些约定。

## 维护与验收

- 实现前以已确认的设计依据建立本次基准，规格与工单引用 `web/DESIGN.md` 及相关页面说明，需要固定版本时记录提交或快照。恢复工作时重新读取引用内容。
- 本次变更引入或调整共享设计规则时，在同一变更中增量维护对应章节。复用现有规则且文档仍准确时无需重写；候选方案和未验证的实现不记成已交付事实。
- 沿用现有章节和源码引用，避免在多个文档中重复维护整套 tokens、组件定义或验收命令。`prototype/` 中的历史演示不作为正式实现标准。
- 验收按 `web/DESIGN.md` 的「维护与验收」执行，并检查本次涉及的操作和状态；全站样式变更遵守其中的页面与视口覆盖要求。构建通过不能替代浏览器中的交互和视觉验收。
- 交付前核对设计基准、实现与验收证据的一致性，同步已确认且通过验收的变化。实现偏离基准时先修复或解决具体设计决策，不为通过验收而倒改规范；在交付说明中列出设计文档维护结果和剩余偏差。
