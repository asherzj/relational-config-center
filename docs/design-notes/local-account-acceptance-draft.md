本文件承接[澄清记录](./local-account-registration-login-sessions.md)中的 Q1–Q20。用户已接受 Q16–Q20 的全部推荐方案，字段规范、维护行为、故障语义、实施参数及 31 条验收用例已冻结，**功能尚未实现**。完整规格已发布为 [GitHub #34](https://github.com/asherzj/relational-config-center/issues/34)；[交付工单拆分](./local-account-ticket-plan.md)已确认并发布为 #35–#40。为保留对话中的文件链接，本文件沿用原文件名。

## Q16：字段规范

| 字段 | 已确认规则 |
| --- | --- |
| Account ID | 系统生成小写、含连字符的 UUID v4，固定 36 个 ASCII 字符，永久不变且不复用；对外和操作人字段均用这一标识，不使用可变名称或数据库自增序号。 |
| 用户名 | 必填，3–32 个 ASCII 字符，以字母开头，其余允许字母、数字、点、下划线和连字符；去除两端空白、统一小写后比较和保存，注册后不可修改。 |
| 邮箱 | 必填，最多 254 个 ASCII 字符，做常规邮箱地址格式校验；去除两端空白，产品明确按大小写不敏感比较和保存，不删除点号或 `+tag`，不按邮箱服务商推断别名。邮箱始终未验证，不用于登录或身份恢复。 |
| 显示名称 | 注册时可省略，默认用户名；显式提供或修改时为 1–64 个 Unicode 字符，去除两端空白，不接受控制字符，不要求唯一。 |
| 密码 | 按 Unicode 码点计 15–128 个字符，原样处理空格与大小写，不去空白、不规范化、不静默截断。 |

用户名和邮箱的唯一性由数据库保证。停用账号继续占用其用户名和邮箱；修改邮箱后释放旧邮箱，不改变账号归属。历史操作人字段继续展示原文；本轮不把普通配置字段里的任意字符串自动解析成账号名称。当前账号入口显示真实显示名称和用户名。

写入 Account ID 的操作人列必须是能够完整保存它的普通文本列；短字段或受限枚举不满足通用账号归因要求时，拒绝变更并返回稳定的字段兼容错误，不泄露数据库原始错误。规则目录列本身足够长；业务表结构由其维护者调整。

## Q17：维护和重新认证

- 普通使用者只有个人资料、修改邮箱、修改密码、退出和退出全部设备能力；不提供账号列表或管理他人账号的 Web/API。
- 停用只针对该账号。由于注册入口开放、邮箱未验证，被停用的人仍可能换一组用户名和邮箱注册新账号；本轮不把账号停用承诺为人员封禁。阻止某个人重新进入需要后续准入/企业身份能力，或由组织在网络访问层控制。
- 服务器维护工具凭部署维护者的数据库权限运行，支持按稳定 ID/用户名查找账号、重置密码、停用、恢复和更正错误登记的邮箱。更正邮箱应由维护者线下核实；邮箱声明本身不能证明账号所有权。工具不能变更 Account ID 或用户名，也不能合并/删除账号。
- 重置密码通过隐藏终端输入或标准输入接收新密码，不通过命令行参数、日志或输出回显密码。新密码仍符合密码规则；重置提交时撤销全部会话。密码的线下告知由维护者负责，本轮不增加邮件或临时密码/强制改密流程。
- 改密和重置密码即使提供与原来相同的密码，也按一次成功操作处理并撤销全部会话。恢复账号不复活已撤销会话，用户必须重新登录。
- 用户修改邮箱需要当前密码；修改邮箱或显示名称不延长会话、不改变 Account ID，也不自动退出其他设备。维护者只更正邮箱时同样不撤销会话；若怀疑账号被盗，应另外重置密码或停用。
- 被停用的已登录账号在重新验证时只能进入通用登录失败状态，不保留可恢复的配置草稿；普通会话过期/撤销可保留草稿等待同账号重新登录。主动退出和换账号仍按已确认规则清除草稿。

## Q18：并发、失效和结果不确定

1. **注册原子性**：账号创建与初始登录会话一起成功或一起失败。两个请求并发抢同一规范化用户名或邮箱，最多一个成功；另一个返回明确的占用冲突。服务已提交而响应丢失时，重新提交可能得到占用提示，用户使用刚创建的凭据登录；不得创建第二个账号或自动绑定已有账号。
2. **登录与撤销竞争**：新会话签发前必须重新确认账号仍启用、密码版本及会话撤销版本未变化。基于旧密码或旧撤销状态开始的登录不能在改密、重置、停用或退出全部设备后补发可用会话；用户可以重新发起一次正常登录。
3. **在途业务请求**：退出、退出全部设备、改密或停用提交之后，尚未通过认证的请求必须拒绝；此前已经通过认证的请求允许完成，并仍归因给原账号。这些动作不撤回已经提交的变更，也不承诺终止已开始的业务事务。
4. **续期**：前台实际交互通过受保护的活动接口报告；只报告活动信号，不上传键盘内容或配置值。正常情况下最多每 60 秒报告一次，成功报告时间由服务器计时；后台查询、后台重试、会话查询不续期。达到 30 分钟闲置或 8 小时绝对期限的会话不可续活；活动上报不能延长绝对期限。前台交互上报失败不能被当成已续期。
5. **多标签页与草稿**：同一浏览器共享一次登录会话；多个标签页的有效活动可维持该会话。退出或账号切换通知其他标签页清除对应数据与未提交输入；迟到的旧账号响应不能覆盖新账号页面。过期时遮住工作区，只有重新验证为同一账号才能恢复内存草稿。恢复后重新检查当前规则和目标数据，用户重新确认后才能写入。
6. **错误语义**：会话失效返回 401；已认证但被既有规则禁止或 CSRF 校验失败返回稳定的 403，403 不跳转登录；账号/邮箱占用返回 409；限速返回 429 和可重试时间；数据库不可用/超时分别保持稳定的 503/504 分类。未知用户名、错误密码和停用账号的登录失败使用相同对外响应，避免暴露账号状态。
7. **结果不确定**：写请求超时、断线或响应丢失后，界面说明结果尚未确认并提供重新查询路径，不自动重放变更。查询可以重试；收到数据库不可用错误时保留会话凭据，恢复后重新验证。会话失效与服务故障不能混为一类。

本轮不增加配置记录乐观并发控制：重新登录后的确认仍沿用现有写入语义；[并发版本工单 #33](https://github.com/asherzj/relational-config-center/issues/33)负责防止两个有效编辑者覆盖彼此的修改。

## Q19：安全实施与升级

| 项目 | 已确认默认值与承诺 |
| --- | --- |
| 密码保存 | Argon2id，独立随机盐；最低参数为 19 MiB 内存、2 次迭代、并行度 1，保存算法与参数便于后续升级；限制并行密码计算，避免注册/登录耗尽资源。 |
| Cookie / Session | 随机、不携带业务信息的 256 位会话令牌；数据库只保存令牌摘要。Cookie 使用 HttpOnly、SameSite=Lax、Path=/、不设置 Domain；正式 HTTPS 使用 Secure 与 `__Host-` 名称，本机 HTTP 使用独立开发 Cookie 名称。 |
| CSRF | 注册、登录、活动续期、个人资料变更、退出及全部业务变更均受保护。提供短期、受容量限制的登录前 CSRF 准备接口，登录时更换会话与 CSRF 凭据；CSRF 凭据不放 URL。非只读请求要求有效 CSRF 凭据以及与配置公开地址一致的 Origin（或可验证的同源 Referer）。 |
| 自动化脚本 | 使用同一公开 Cookie 接口：先取得 CSRF 凭据与 Cookie，再以配置的 Origin、Cookie jar 和 CSRF 头登录/调用/续期；过期后重新登录。无额外部署 Token、API Key 或服务账号豁免；交付可复制的脚本示例。 |
| 登录限速 | 每个规范化用户名 15 分钟内最多 10 次失败，达到阈值后等待窗口结束；每来源 IP 每分钟最多 60 次登录尝试。未知用户名也适用，成功登录清除该用户名失败计数。 |
| 注册限速 | 每来源 IP 每小时最多 10 次注册提交；用户名和邮箱唯一冲突也计入。参数可配置，超额返回 429 与 Retry-After；限制是暂时拒绝请求，不改变 Account Status。 |
| 限速持久化 | 计数与必要时间窗保存在受保护的 MySQL 控制表中，正常重启不清空限制；过期会话、登录前凭据与限速记录有明确的清理和容量上限。限速依赖故障时拒绝认证请求，不能悄悄放行。 |
| 网络边界 | Web/API 同源；公开地址来自显式部署配置，不从任意 Host 或转发头猜测。正式内网入口使用 HTTPS，同源代理后面的 Admin 不单独向使用者开放；提供代理示例。本机 HTTP 例外须明确启用并使用 loopback 对外地址。仅信任显式配置的代理来源解析客户端 IP。 |
| 数据与日志 | 不把密码、会话令牌、CSRF 凭据、邮箱、完整 Cookie/敏感头或配置值写入日志、URL或前端持久存储；记录请求 ID、稳定错误类别和安全的操作结果。 |

密码、会话和 CSRF 基线来源：[OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)、[Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)、[CSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)。会话时长和限速数字是本项目的业务参数。

升级采用可安排维护窗口的一次切换：备份并停用/摘除全部旧 Admin 入口，执行显式控制表迁移，更新代理、配置和脚本，启动新版验证后开放入口。新装直接创建最终控制表；账号表为空是可用状态，可供首次自行注册。旧版本不能继续并行接收共享 Token，不承诺滚动无停机升级。

新版 Admin 启动和 readiness 检查所需认证表与关键列/约束；结构未升级时拒绝启动并给出操作指引。数据库维护工具使用独立的维护连接初始化，不以“正常 Admin 已经就绪”为前提。旧 Token/免认证配置应明确报错，避免部署者误以为仍生效；迁移工具需要的历史 Operator 输入与正常运行配置分离。

## Q20：验收入口与用例

主验收通过公开 HTTP 接口和真实 MySQL 8.4 完成，正常测试经真实注册/登录取得 Cookie，不能以关闭认证替代。进程/维护命令测试证明启动、升级、重启和运维权限入口；Web 组件测试证明表单、遮罩、草稿和标签页状态；增加一条真实浏览器系统路径验证 Web、同源代理和 Admin 的实际连接。每项行为只设一个主要证明层，不在每层机械重复。

下面是带稳定编号的代表性用例；`to-spec` 会把同一内容展开为完整 Given/When/Then 和证据，不重新改变语义。

| 编号 | 前提与动作 | 应观察到的结果 | 主要证据 |
| --- | --- | --- | --- |
| AC-001 | 新装且无账号，访问受保护页面 | 进入登录/注册入口，健康检查正常，无默认特权账号 | HTTP / Web |
| AC-002 | 提交合法注册资料 | 账号即启用、自动登录、显示真实身份；邮箱未验证，无邮件调用 | HTTP + MySQL |
| AC-003 | 并发注册规范化后相同的用户名或邮箱 | 恰好一个成功，其余占用冲突，无重复账号或部分注册 | HTTP + MySQL 并发 |
| AC-004 | 用户名/邮箱/名称/密码处于合法边界或非法输入 | 按字段规范接受或拒绝；密码不静默规范化/截断 | HTTP；复杂字符边界可辅以纯规则测试 |
| AC-005 | 提交错误密码、未知用户名或停用账号 | 相同安全的登录失败，不产生可用会话 | HTTP |
| AC-006 | 登录/注册超过限速，或伪造来源头 | 返回 429 与等待时间，不能用伪造头绕过；窗口结束可恢复 | HTTP + MySQL |
| AC-007 | 访问登录前保存的站内目标，或恶意站外目标 | 登录后回合法原目标，站外/协议相对目标落默认页 | Web |
| AC-008 | 注册/登录或其他状态变更缺少合法 CSRF 凭据/来源 | 拒绝，账号、会话或业务内容不发生变更；脚本按文档可正常调用 | HTTP |
| AC-009 | 未认证或只携带旧部署 Token 访问业务 API | 返回 401，不能读取或修改；健康接口仍可用 | HTTP |
| AC-010 | 同一账号多设备登录、刷新和重开浏览器 | 多会话可并存，未过期会话恢复，浏览器不存部署 Token | HTTP / 浏览器 |
| AC-011 | 浏览器后台自动请求，或前台真实交互报告活动 | 后台请求不续期，有效活动可续闲置期；到 30 分钟/8 小时边界失效 | HTTP 可控时钟 + Web 活动测试 |
| AC-012 | 普通退出当前设备 | 当前会话及同浏览器标签失效，其他设备仍可用，当前草稿清除 | HTTP + Web 标签通知 |
| AC-013 | 退出全部设备、改密或维护命令重置密码 | 所有旧会话失效；旧密码登录按改密结果失效 | HTTP + 命令 |
| AC-014 | 登录签发与改密/重置/停用/全部退出并发 | 旧认证状态不能补发有效会话；用户重新发起登录按新状态裁决 | HTTP + MySQL 并发 |
| AC-015 | 请求已通过认证时另一路撤销会话 | 在途请求可完成且归属原账号；撤销后未通过认证的请求被拒绝 | HTTP + MySQL 并发 |
| AC-016 | 有未提交输入时会话过期 | 工作区遮住；同账号重登恢复内存输入、重新确认后提交；不自动重放 | Web |
| AC-017 | 草稿存在时换账号、主动退出、刷新或收到旧账号迟到响应 | 草稿按规则清除，旧数据不能进入新账号页面 | Web |
| AC-018 | 已登录用户修改显示名称或凭密码修改邮箱 | 资料更新、邮箱唯一且未验证；Account ID/用户名不变，错误密码不改资料 | HTTP |
| AC-019 | 普通用户尝试读取账号列表或管理他人 | 没有可用的账号管理接口；自己的管理台功能继续正常 | HTTP |
| AC-020 | 维护命令停用、恢复或更正邮箱 | 停用立即阻止后续认证，恢复不复活会话；更正保持唯一性和账号归属 | 真实命令 + HTTP |
| AC-021 | 两个账号同时写配置行及三种规则目录 | 每笔创建人/修改人来自对应账号，无固定值或并发串用身份 | HTTP + MySQL |
| AC-022 | 历史操作人或不能容纳 ID 的业务字段 | 历史值不改、不猜归属；不兼容写入明确拒绝，业务内容不变 | HTTP + MySQL |
| AC-023 | 已认证账号执行被表规则禁止的操作 | 稳定 403；不跳登录，规则/Schema/Auto Fill 仍执行 | HTTP / Web |
| AC-024 | 有有效会话时正常重启 Admin | 会话与尚未结束的限速窗口保留，过期会话不复活 | 进程 + HTTP |
| AC-025 | 数据库不可用、超时或认证表结构未升级 | 故障分类稳定，不退回匿名/共享 Token；缺结构启动失败，空账号库可启动 | 进程 / HTTP |
| AC-026 | 注册、写入或改密已提交但响应丢失 | 不自动重放写入；注册可用原凭据登录，业务可重新查询，旧会话按实际改密结果裁决 | HTTP 故障注入 + Web |
| AC-027 | 按文档升级已有库，并运行维护工具 | 最终结构可用，旧入口停用；维护工具不被正常 Admin 就绪检查锁死 | 进程 + MySQL |
| AC-028 | 在正式 HTTPS / 显式本机 HTTP 配置下登录 | Cookie 属性与环境匹配；日志、URL和持久浏览器存储不含敏感凭据 | HTTP / 进程 |
| AC-029 | 浏览器从未登录访问一路完成注册、配置变更和退出 | Web 经实际代理访问 Admin，真实操作人正确，退出后不能继续业务访问 | 一条浏览器系统路径 |
| AC-030 | 已登录账号尝试发现或通过通用规则/数据接口操作账号、会话和限速控制表 | 控制表不可被发现或纳入管理，不能修改凭据、会话或解除限速 | HTTP + MySQL |
| AC-031 | 伪造、篡改或重放已过期/撤销的会话令牌，或尝试沿用登录前会话 | 不能取得身份；登录成功更换会话凭据，旧凭据不获得新权限 | HTTP |

## 明确的范围与后续

本轮交付账号与会话、个人资料、服务器维护命令、现有归因字段、旧认证切换、部署和脚本文档，以及上述验收。统一当前身份接口只为后续身份接入保留边界；不在本轮实现 OIDC/企业 Adapter、角色差异、持久审计、邮件、MFA、账号删除/合并、多租户、公网部署、配置乐观并发控制或高可用/滚动升级承诺。

不需要为当前对话已能确定的行为制作原型。正常注册、登录等凭据输入界面沿用现有 Web 设计；其状态正确性由上述行为测试验证。
