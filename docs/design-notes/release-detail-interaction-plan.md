# 发布单详情交互优化方案

状态：已交付。用户于 2026-09-08 完成四轮确认，D-001～D-017 全部敲定；2026-09-09，#60～#64 均已验证并交付，16 条验收要求都有证据。本文保留已确认的范围与验收依据，结果见[验收索引](../verification/2026-09-09-release-detail-acceptance-index.md)。

决策来源见[讨论记录](release-detail-interaction-discussion.md)，发布后快速回滚边界见 [ADR-0023](../adr/0023-keep-published-orders-open-for-quick-rollback.md)。

## 要解决的问题

发布单详情需要按用户提供的截图组织信息，让查看者快速理解当前阶段、审阅字段变化并执行有权限的下一步。普通配置发布成功后保留待完结阶段，有发布权限的人可快速回滚或明确完结；记录在此期间继续占用。

本次覆盖详情页全部状态，沿用现有全站外观。列表及草稿入口仅补标题、新状态和必要跳转衔接。采用真实单号、英文字段名和当前人员姓名；没有旧发布单数据，不做旧单数据兼容、日期流水编号或通用字段显示配置。

## 已确认的业务路径

普通发布：草稿 → 提交审批 → 他人批准 → 执行发布 → 已发布待完结。

- 待完结时，当前有发布权限的人可以快速回滚，无需再次审批；不限定原执行人。
- 确认完结关闭快速回滚入口并释放占用；以后恢复仍通过普通回滚发布单重新审批。
- 快速回滚与普通审批回滚成功后，原单已回滚，回滚结果自身也结束并释放占用；再次发布需要新建普通发布单并审批，不再提供“回滚这次回滚”。
- 未发布的已批准普通单可重新准备：有编辑权限的原申请人或 ADMIN 执行，原单取消并创建新草稿，新申请人是实际操作者，修改后重新审批。取消旧单和创建新草稿必须共同成功或共同失败；明确失败时原审批与占用保持原状。
- 同表无重叠记录的其他发布继续执行。回滚不得覆盖后续数据库改动；任何失败不能伪造成功结果。

## 页面和状态

| 状态 | 主要展示和操作 | 记录占用 |
| --- | --- | --- |
| 草稿 | 标题、明细、编辑、提交审批、取消草稿 | 不占用 |
| 待审批 | 冻结申请、独立批准/拒绝、允许的取消 | 占用 |
| 待发布 | 审批结果、整单执行、重新准备、允许的取消 | 占用 |
| 已发布待完结 | 真实发布结果、确认完结、快速回滚 | 继续占用，包括新增实际 ID 和删除身份 |
| 已完结 | 完结人/时间、原发布结果、申请普通审批回滚 | 原发布已释放；新的回滚提交按既有流程占用 |
| 已拒绝/已取消 | 意见、历史及允许的复制草稿 | 不占用 |
| 已回滚 | 回滚结果、原发布及关联历史；不直接重新发布 | 释放 |
| 回滚执行成功的结果记录 | 展示恢复结果及原发布关联，直接结束；无再次完结或反向回滚入口 | 释放 |

表中操作均以当前权限、真实状态和发布单版本为准。请求处理中、明确失败和结果未知是独立反馈，不能把超时显示为已回滚、已完结或已释放占用。“已完结”行的申请回滚指普通发布单；成功的回滚结果不开放该入口。

页面依次为：返回列表与面包屑；准备/审批/发布/完结步骤；标题及基础信息与操作区；变更内容；真实发布/回滚结果；操作历史。手机采用单列，宽差异表在局部滚动；英文字段名、长值和真实 ID 可完整查看。

## 工作拆分

| 工作包 | 交付内容 | 依赖 |
| --- | --- | --- |
| 1. 发布后状态与占用 | 待完结、完结动作/历史/权限；普通发布成功保留目标；新增实际 ID 补占用、删除身份持续占用；完结释放 | 已确认 D-003～D-007 |
| 2. 快速回滚与收尾 | 有发布权限者免审批整单恢复；复用可信发布前值及版本检查；反向写入与已有占用协调；结果和原单终止一致；普通审批回滚保留 | 工作包 1；D-016 |
| 3. 标题、人员与重新准备 | 创建/编辑/读取标题；普通查看者可读取单据相关人员当前姓名；取消旧单与新草稿共同成功或失败，保存新申请人、来源关联及可恢复请求 | D-014/D-015；标题规则 D-017 |
| 4. 详情交互 | 布局、步骤、信息卡片、操作区、计数/折叠/过滤、结果切换、时间线、复制反馈、移动与键盘操作；列表最小衔接 | 工作包 1～3；D-017 |
| 5. 完整验收与文档 | 真实 MySQL 的事务和并发验证；Web 定向检查、真实浏览器主流程；更新当前契约和操作说明 | 工作包 1～4 |

建议先实现发布后状态与占用，再实现两类回滚收尾；标题、人员和重新准备可作为独立工作推进，之后接入完整详情交互并进行整体验收。每个工作包同时验证自身的业务行为，最后一包补齐跨流程验证。

## 实现必须保留的保证

- 当前 PUBLISHER/ADMIN 可快速回滚和完结，原发布人不是额外条件。申请、审批、发布、回滚和完结分别记录实际账号标识；显示名不替代身份。
- 普通审批仍禁止自批；快速回滚直接记录其合法授权路径，不伪造 APPROVE。
- 发布、回滚、完结使用当前所见版本和稳定请求标识；同一请求可找回结果，两个竞争动作不能同时对同一版本成功。
- 业务记录、记录/表版本、发布和回滚结果、占用变化、历史及成功请求结果保持原有事务一致性。
- 快速回滚只能根据真实已保存发布结果恢复，不能接受客户端声称的历史原值或自动接受最新记录版本。
- 记录占用按真实数据库身份；未知自增 ID 在执行成功事务中补齐，删除后的身份继续保护。回滚不能先释放占用再竞争写入。
- 明确失败保留原状态和必要占用；未知结果按原请求恢复。界面隐藏或禁用按钮不能代替服务端状态和权限检查。
- 重新准备在取消旧单前重验当前配置和原单版本，在同一事务内完成旧单状态与占用释放、新草稿及双方历史/关联、成功请求结果；不得出现旧审批已丢失而新草稿未生成的部分结果。
- 新字段与状态同步更新服务端、Web 契约、安装结构、错误说明和测试数据。无需旧发布单数据迁移，但新功能创建的数据必须可以稳定重读和恢复请求。

## 验收要求

以下是计划验证的行为，不表示已经通过。

1. 普通单发布成功进入待完结，并阻止其他单提交重叠记录；同表不重叠记录正常提交。
2. 自增新增产生的真实 ID 和已删除的 ID 都在待完结期间受保护。
3. 另一位当前有发布权限的人可以快速回滚和完结；只有查看、编辑或审批权限的人不能执行这些新动作。
4. 快速回滚不等待新审批，整单恢复原业务值，保存真实执行人/结果/历史，释放占用且原单已回滚。
5. 某一项数据、规则、表结构或恢复结果校验失败时整单不生效，状态、版本及占用不留下部分结果。
6. 快速回滚和完结竞争、两次回滚竞争均至多产生一个有效结果；响应丢失后重试不会重复恢复或重建结果。
7. 完结只结束快速回滚阶段，不修改业务内容或冒充下游已收到配置；普通审批回滚仍可申请，原单不重新打开。
8. 普通审批回滚成功也直接结束、释放占用，不出现新的待完结或连续反向发布入口。
9. 重新准备仅允许仍有编辑权限的原申请人或 ADMIN；新申请人为实际操作者且不能自批。明确失败保留旧审批和占用，成功同时形成取消原单和新草稿；丢失响应后能找回同一结果。
10. 标题必填、最多 100 字、创建时正确预填，在所有建单与草稿修改入口一致保存；提交后不能修改，过期版本不能覆盖新的标题或明细。
11. 普通查看者能看到单据相关人员的当前姓名，账号改名不改变历史归属；无法解析时有 ID 兜底，不依赖 ADMIN 账号列表权限。
12. 仅看变更正确处理 NULL、空字符串、未提交和系统生成状态；新增/删除完整可读；千项分页不改变整单操作范围。
13. 申请值、实际发布值和回滚结果有明确区别，默认值与生成字段不被申请内容冒充。
14. 各状态的步骤、主次操作、时间线、关联单、复制反馈及刷新后的信息正确；历史默认最近 5 条且可完整查看，窄屏和键盘均能完成必要操作。
15. 快速回滚只有在查看恢复差异、填写原因并确认后执行；完结确认清楚说明占用释放和快速回滚关闭，取消确认不改变业务状态。
16. 请求中或结果未知时，不允许通过重复点击、刷新、会话恢复或另一个终止动作制造重复恢复、提前完结或部分占用释放；当前权限变化按已有认证和幂等边界处理。

验证采用项目现有 Web 类型检查/构建及定向测试，结合真实 MySQL 与正式浏览器入口覆盖改动涉及的路径。只修改讨论文档期间执行文档检查，不以文档检查宣称上述功能已验证。

## 已确认交互细节

### 标题与基础信息

标题必填，最多 100 个 Unicode 字符；创建草稿时预填“表名 配置变更”，草稿阶段可改，提交后冻结。复制带入原标题供新申请人修改，普通审批回滚使用从原单标题生成的标题。单号保留完整真实 ID，复制后给出反馈；显示创建时间及明确标注的发布单版本。

人员显示当前账号姓名和首字头像，永久账号 ID 可查看且作为无法解析姓名时的兜底。姓名展示可供普通查看者使用，接口提供本单相关人员的展示信息，历史归属仍由永久 ID 确定。

### 审阅差异与实际结果

首次打开默认仅看变更、展开第一项，保留每页 20 项和整单操作语义。MODIFY 隐藏确定不变的字段，自动填写和数据库生成字段保留待生成说明；ADD/DELETE 展示完整记录。SQL NULL、空字符串、未提交和记录不存在分别表达。

发布前显示原值和申请值；成功后默认显示实际发布结果，可切回申请差异。已回滚时醒目展示状态，并提供真实回滚结果及原发布结果。不得用申请值推测数据库默认值或生成字段的最终值。

### 步骤、历史与确认

步骤条展示准备、审批、发布、完结的真实进展，不支持点击跳过步骤。准备完成时间取提交事件；批准、发布、完结采用各自事件中的操作人和时间。拒绝、取消和回滚显示真实终止结果，不能渲染为四步正常成功。

历史默认最近 5 条倒序展示，支持查看全部及关联单跳转。快速回滚先核对恢复差异、填写原因，再确认执行；完结二次确认释放占用并关闭快速回滚，不强制额外意见。
