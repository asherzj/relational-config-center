# T5：异常报错、安全重推与失败历史

状态：用户已确认切片及依赖；ready-for-agent。

## 父工单

Part of #81：https://github.com/asherzj/relational-config-center/issues/81

## 要构建什么

发布或回滚异常时用户看到真实错误，不自动重试，也不进入独立结果确认流程；用户再次点击原操作时后端按原业务请求安全重推。明确失败记录操作历史，数据库不可用导致未保存时如实提示。

## 验收标准

- [ ] 真实业务值、结构、规则、唯一键、外键或事务失败整单无部分结果；成功执行表不保存失败尝试。
- [ ] 已确认未提交才能标记执行失败，未知提交不冒充失败；失败历史另行留痕不得破坏业务原子性。
- [ ] 无法保存失败历史时明确提示，不能伪造历史已落库或为记录失败留下业务写入。
- [ ] 同一业务请求已成功返回原结果，未提交允许原子执行，同键异内容拒绝；后端保持当前权限和状态版本校验。
- [ ] 前端只报错，不自动重试或提供独立确认按钮；保留安全重推所需的原请求身份，刷新读取真实主单状态。
- [ ] 响应丢失、重复点击、回滚/完结竞争不产生重复业务变更、版本、通知或成功执行记录。

## 验收用例

唯一主要交付：AC-011, AC-012。采用父规格Given/When/Then；其他相关用例是必要的回归和跨切片证据，不重复分配主要责任。

真实MySQL故障与并发集成证明部分步骤失败、提交结果丢失、重复及竞争；HTTP证明错误/失败历史可用性；浏览器证明网络异常后不自动发请求、用户重推原操作、没有额外确认流程。
