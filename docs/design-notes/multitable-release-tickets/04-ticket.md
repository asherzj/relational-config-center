# T4：复制与重新准备的跨表占用流转

状态：用户已确认切片及依赖；ready-for-agent。

## 父工单

Part of #81：https://github.com/asherzj/relational-config-center/issues/81

## 要构建什么

用户从已拒绝或取消单复制草稿时重新读取多表数据并竞争全部占用；从已批准未发布单重新准备时原子转移到新草稿。冲突清晰可见，不留下半张新单或失去源单保护。

## 验收标准

- [ ] 复制任一明细冲突则整次失败，无新单及占用残留，显示表、占用单号和负责人。
- [ ] 重新准备同事务取消源单、创建新草稿、转移仍需目标、取得新增目标；失败源状态与全部占用保留。
- [ ] 新草稿归属实际操作者并重新审批，不继承原审批，保留真实新旧关联。
- [ ] 多表顺序与明细意图完整，使用当前基线，不在后台静默覆盖已批准内容。
- [ ] 沿用当前权限边界，错误保留用户已确认内容；幂等重推不重复创建派生单。

## 验收用例

唯一主要交付：AC-008。采用父规格Given/When/Then；其他相关用例是必要的回归和跨切片证据，不重复分配主要责任。

HTTP+真实MySQL证明跨表占用竞争、任意步骤故障原子性和重推去重；浏览器证明复制/重新准备确认、冲突定位、新旧关联及重新审批。
