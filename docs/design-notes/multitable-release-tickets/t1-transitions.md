# #81 最终接口边界（T7 / #88）

T1～T6 使用的临时结构已退出。以下记录最终职责，也保留维护后续代码时必须遵守的事务和身份约束。

| 原结构 | 最终状态与所属职责 |
| --- | --- |
| 主单 `TableName` / `Frozen`、输入默认表、首表版本/通知别名 | 已删除。每项申请明确所属表，冻结定义按表保存，每表版本和通知各自归属。空草稿只需标题。 |
| 整单 `PublicationResult` / 根级 `Publication` / `Rollback` 结果外观 | 已删除。主单 GET 返回摘要；版本绑定的详情页读取每项申请及其两次实际结果，成功执行只提供最多两条摘要。页结果保持原始明细位置。 |
| `ReleaseOrder.Items` 与事务内 `PublicationCommit.Commands` | 由原子草稿保存、冻结及共享执行器持有；最大 1,000 项仍作为一个事务验证和提交。不能以读取分页拆分执行。 |
| `rcc_release_requests.result` 的原申请及流程快照 | 由原键业务确认负责精确恢复当时响应。实际执行结果引用原始不可变明细，不另存完整 commands。当前权限重新验证，当前主单另外读取，旧响应不能覆盖后来的终态。 |
| 编辑、复制、重新准备与已知冲突审阅所需完整申请 | 调用方明确收集同一版本的全部详情页；任一页失败不得采用部分结果。通用主单读取不自动回填全部明细。背景主单刷新可以撤销动作，不得替换本地输入、原基线或原请求日志。 |
| 独立回滚字段、动作、拒绝路由及 UI 关联 | 已删除。旧 `/rollback` 返回路由不存在；只有原单快速回滚，无新单或新审批。 |
| 未知结果确认包装与门禁 | 已删除。原业务按钮手动重推 IndexedDB 中原账号、原键和完整正文。保留已知冲突 `ReleaseRequestReview`，明确审阅后才能重建。 |
| 旧字段/整单/结果字节预算常量和错误枚举 | 已删除。数量边界是整单 1,000 项；接受明细的已注册路由解除旧 envelope 限制，无关 API 保留现有限制。内部 SQL 批次始终属于一个事务。 |

草稿内容和目标写入沿用同一个 `ReleaseOrderSession` 事务，先锁原请求再锁主单，随后读写明细。主单 `item_count` 决定当前已有明细的完整主键集合；空明细不取子表范围锁，增删时只锁实际存在的明细键，不能恢复为 `order_id` 空范围 `FOR UPDATE` 或无条件删除末尾范围，否则独立原单会因 MySQL 间隙锁互相阻塞。执行摘要同样按状态读取已存在的完整 `(order_id, kind)` 主键。锁定读取必须看到当前已提交值，不能改成事务内先前 RR 快照的普通读取。Adapter 的并发空明细和已有明细增长验收覆盖此协议。

`position` 为零基整单顺序，`detail_id` 是稳定的单内身份。草稿按明细身份增量保存，排序仍提交完整身份序列和整单版本。`rcc_release_details` 每行保存 `application`、`publication`、`rollback` 三列 JSON；实际逆向 Command 归原始明细，执行计划严格倒序。成功执行键 `(order_id,kind)` 限定发布和回滚各一次；通知主键为 `(execution_id,table_name)`。原申请和原发布结果不可被恢复覆盖。

成功回滚后可由真实回滚执行人或当前 ADMIN 补填、修正或清空原因，每次追加不可变历史并关联稳定执行 ID；不改动执行事实或业务版本。不转换旧发布单，不双写，不自动清理环境。当前安装与恢复边界见 [Goose 迁移手册](../../schema-migrations.md)，操作接口见[发布草稿](../../admin-release-drafts.md)和[原单回滚](../../admin-release-rollbacks.md)。
