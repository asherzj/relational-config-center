# T6：回滚原因的事后补填与修改留痕

状态：用户已确认切片及依赖；ready-for-agent。

## 父工单

Part of #81：https://github.com/asherzj/relational-config-center/issues/81

## 要构建什么

回滚执行人或管理员在原单事后选填或修正原因，每次修改记录操作者、时间和内容，不重开发布单或改变真实执行结果。

## 验收标准

- [ ] 本次回滚执行人或管理员允许补填和修改，其余账号拒绝，不能将原申请人当作回滚执行人。
- [ ] 历史保留各次真实内容、修改人和时间；执行明细、版本及实际结果不被改写。
- [ ] 原因无必填、期限或提醒，不阻塞其他发布。
- [ ] 原因写入遵守权限、事务和幂等，明确错误保留输入，不增加独立确认流程或自动重试。
- [ ] 接口和页面均可用，桌面390px及键盘访问通过验证。

## 验收用例

唯一主要交付：AC-013。采用父规格Given/When/Then；其他相关用例是必要的回归和跨切片证据，不重复分配主要责任。

HTTP+MySQL证明授权、历史持久化和重复写入结果；浏览器证明补填/修改/历史及错误保留；独立断言原因不写业务表、不再次执行回滚。
