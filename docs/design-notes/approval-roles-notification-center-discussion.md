## 第一轮已确认

用户对 Q1、Q2、Q3 分别回复“同意”。

### Q1：新角色与现有全局权限

已确认新增可自定义的审批角色，例如“运营审批”“财务审批”，由管理员维护角色及人员；查看、编辑、发布和平台管理继续使用现有全局权限。按表审批资格由表配置及角色成员关系决定，旧全局 `APPROVER` 不再单独授予全表审批权，`ADMIN` 也须命中该表角色，所有人仍不得自审。

后续 Q5 用户明确增加“默认 ADMIN 审批”，因此上述 ADMIN 必须命中表角色的限制增加默认审批例外；不据此恢复 ADMIN 对所有配置角色表的无条件审批权，已确认触发边界见 Q10。

### Q2：同表多角色与多表审批通过条件

已确认一张表可以分配多个审批角色，任一角色中的一人批准即满足该表审批；一张发布单涉及多表时，每张表都需获得对应角色成员批准，全部满足后才允许整单发布。同一人可一次批准其有权审批的多张表，任一有效拒绝终止整单。这是对 #81 所沿用的全局单人审批规则的后续调整，本会话不直接改写另一功能规格。

### Q3：通知中心中“所有审批”的范围

已确认提供“待我审批”“我发起的”“我已处理”“全部审批”，默认待我审批；全部审批展示本部署所有已提交发布单及其后续状态，查看范围沿用现有全局查看权限。角色限制操作资格。点击记录进入发布单详情审阅和处理。

## 第二轮确认结果

用户对 Q4、Q6、Q7、Q8、Q9 回复“同意”，对 Q5 回复“默认ADMIN审批”。

### Q4：角色或表配置变化如何影响已提交的申请

已确认提交时固定每张表可用的审批角色，角色成员按当前状态检查：移出成员即失去后续审批资格，新加入的成员可接手未完成审批。已经合法通过的表审批保留，之后更改表绑定的角色只影响新提交的申请。需要改变旧申请的审批角色时取消并重新提交。

### Q5：没有合格审批人时如何处理

用户明确修正为“默认 ADMIN 审批”。原先“任何无合格审批人的表一律禁止提交、在途申请等待补充成员”的建议没有被接受，不再作为默认规则。Q10 已确认覆盖表未配置角色、已配置角色无人可审及途中失去全部审批人，所有人禁止自审的约束保留。

### Q6：部分表已通过后还能否重复处理

已确认每次批准覆盖当前用户有权审批且仍待审批的全部表，确认时明确列出范围；已通过的表不重复批准，也不能再以该表资格拒绝整单。其他未通过表的合格审批人仍可拒绝整单。并发处理导致审阅版本变化时保留意见并要求读取最新进度后再操作，不静默扩大或缩小刚确认的审批范围。

### Q7：角色管理的维护与退出方式

已确认管理员可新建角色、修改名称/说明、增删成员、启用/停用；角色可暂时没有成员，但不能因此自动获得审批资格。被表绑定或历史审批引用的角色不可物理删除，停用后不能产生新审批，历史名称与真实身份仍可追溯。仅从未被引用的角色允许删除。

### Q8：旧全局审批权限如何切换

已确认撤下账号角色页面及新授权接口中的 `APPROVER`，保留已有查看/编辑/发布/管理权限，仅有旧 `APPROVER` 的账号保留查看能力；不自动生成覆盖全部表的审批角色。由管理员明确建立审批角色、成员和表绑定，未配置时采用用户修正后的 Q5 默认 ADMIN 规则，不能继续写成一律拒绝提交。发布单数据兼容范围沿用 #81 已确认的无旧单数据迁移边界，不把这一点解释成删除任何环境数据的授权。

### Q9：通知中心是否提供未读提醒及其范围

已确认做站内未读提醒：新待办通知当前可审批成员；每次审批进展、拒绝或取消通知申请人；发布、完结和回滚结果通知申请人及已参与审批的人。同一人对同一发布单的提醒合并为一项，自己触发的操作不再提醒自己；打开详情标记已读，后续新变化重新变为未读。待审批数量独立计算，阅读不会使待办消失；“全部审批”中的无关单据不计入个人未读。

## 第三轮已确认

用户对 Q10、Q11、Q12 分别回复“同意”。

### Q10：默认 ADMIN 审批何时触发

已确认覆盖 Q5 的全部无人可审场景：未配置角色、全部角色停用、角色中没有启用且不是申请人的成员，以及审批途中失去最后一名合格成员时，由当前已启用且不是申请人的 ADMIN 接手该表。只要仍有合格角色成员，就仍按已配置角色审批，ADMIN 不额外获得资格；有合格成员恢复时，尚未完成的 ADMIN 兜底资格退出。角色与表范围仍按 Q4 的提交快照判定，已合法完成的 ADMIN 审批保留。

申请人若恰好是唯一 ADMIN，仍不能自审：无其他合格审批人时拒绝新提交；已提交申请保留并提示补充成员或另一名 ADMIN。默认是由人执行审批，不是自动批准。

### Q11：资格变化后，个人待办与未读如何变化

已确认新增资格时补充未完成表对应的待办提醒，同一账号同一发布单保持一项；失去资格或其他人已完成本人可审的全部表时，移除“待我审批”及仅由失效待办产生的未读提示。本人申请、已处理记录和相关结果提醒继续保留；通过“全部审批”仍可查看该单。重复刷新和同一事件重试不制造重复提醒。

### Q12：通知刷新与失败行为

已确认进入页面或回到页面时刷新，停留期间每 30 秒刷新一次，并提供手动刷新；不承诺后台实时推送。审批等业务状态变化和对应通知一起保存，任一保存失败则该次业务操作不成功；超时保留原请求身份，重推不重复审批或通知。标记已读失败不妨碍查看详情，但保留未读并可重试；标记已读只覆盖已看到的进度，不能吞掉并发到达的新通知。
