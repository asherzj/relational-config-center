# T5（#52）：正式发布单条配置并删除旧直写入口

状态：用户已确认；ready-for-agent。

## 父工单

Part of #48：管理台正式发布闭环规格。

## 要构建什么

发布者手动执行一张已批准的单条 ADD/MODIFY/DELETE，配置与最终态变更、版本、历史和通知记录共同生效。数据页确认统一改为保存草稿，旧 HTTP 写入口和旧 Web 调用被删除，用户再也不能通过原接口绕过审批。失败、未知结果和成功有准确可恢复的行为。

## 验收标准

- [ ] 只有当前有发布权限且状态/版本有效者能执行；审批人可兼发布人，申请人可执行别人批准的自己的单据，仍无自批通道。
- [ ] 真实业务写入、记录版本、最终行变更、表版本、状态/日志/占用释放及通知记录同事务提交；任一步失败完整回滚。
- [ ] ADD/MODIFY 读取并编码数据库完整最终行，DELETE 表达删除；类型与 Schema 摘要/校验和无歧义，实际 id 与记录并发身份正确。
- [ ] 冻结内容与当前数据/Schema/变更规则语义重验，名称/描述修改不误伤；不可完整追踪的附带写入在修改业务数据前拒绝。
- [ ] 记录实际执行人的永久 Account ID 与数据库时间，分别保留申请、审批、执行身份。
- [ ] 明确失败保持 APPROVED 与占用；执行/取消和重复执行竞争有唯一结果；丢响应、提交不确定及进程重启均通过原幂等标识收敛。
- [ ] 发布详情展示实际结果、关联版本/变更和通知记录；显示分发未接入，不启动假投递器。
- [ ] 数据页确认统一保存草稿；删除旧记录写路由、旧 Web 写调用和其他过渡调用方，不留旁路/免审批兼容开关。
- [ ] 更新现有脚本与验收路径，保留并迁移 #33 的长期并发保证；旧客户端写请求明确拒绝。

## 验证证据

真实 MySQL 验证三种发布、默认/生成/支持的触发器最终行、删除、陈旧基线和逐类事务失败；稳定 Codec 样例独立证明无损编码。HTTP/真实进程证明丢响应与重启恢复、执行/取消竞争。Web 证明确认变成草稿、实际发布和未知结果交互。负向 HTTP 和静态调用检查证明所有旧直写能力已删除；运行必要全套回归及两轴评审。
