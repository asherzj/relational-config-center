# T3（#50）：从数据页保存和管理发布草稿

状态：用户已确认；ready-for-agent。

## 父工单

Part of #48：管理台正式发布闭环规格。

## 要构建什么

编辑者可以将一条现有配置变更保存为草稿，查看服务器核实的字段差异，刷新后继续编辑；发布单列表可按表、申请人和状态查找，取消的草稿保留历史。保存草稿不会修改业务记录，也不占用目标。

## 验收标准

- [ ] 保存单条 ADD/MODIFY/DELETE 草稿，记录稳定申请人、表、内容、原值和记录基线，业务数据未变。
- [ ] 只有本人且当前有编辑权限能修改，发布单版本阻止多窗口覆盖；服务器拒绝伪造 before 和自动字段。
- [ ] 完整差异保留 NULL、空字符串、未提交及不存在等语义。
- [ ] 具查看权限者可分页筛选及按单号查看详情；动作由实际身份和状态决定。
- [ ] 取消草稿保留记录，不允许物理删除，已取消草稿不能重提。
- [ ] 所有草稿写操作具备幂等标识及摘要检查，丢响应同键重试找回原结果。
- [ ] 在现有数据页提供明确的保存草稿入口，并提供正式发布单列表/详情界面；T5（#52） 再统一切换默认确认动作。

## 验收用例

主要负责：AC-012、AC-013、AC-014、AC-015、AC-016、AC-017。

## 验证证据

HTTP 证明内容、所有权、版本和幂等；真实存储证明刷新恢复、历史及无业务写入/目标占用；界面定向验证创建、查询、编辑冲突和取消。

## 临时结构与退出条件

本单只先允许一个明细，T6（#53） 负责删除单条上限并扩展同表集合。既有默认确认/直接写调用暂留到 T5（#52） 统一切换和删除；不声称草稿已生效，也不生成假执行结果。
