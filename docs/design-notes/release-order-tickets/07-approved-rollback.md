# T7（#54）：以新发布单审批并执行回滚

状态：用户已确认；ready-for-agent。

## 父工单

Part of #48：管理台正式发布闭环规格。

## 要构建什么

编辑者从已发布详情申请反向草稿，经另一审批人确认后由发布者执行。回滚恢复原单涉及的业务值，保留本次操作人和时间，不能覆盖后续变化；原发布、反向发布及版本历史清晰关联。

## 验收标准

- [ ] 单条与混合批量均可生成有关联的反向草稿，沿用正式提交、审批和执行能力，不能直接回滚写库。
- [ ] 反向基线来自原发布的实际结果和记录版本，不能悄悄接受当前较新值；原结果被后续变更时明确拒绝。
- [ ] 恢复业务字段，自动操作人/时间记录本次回滚，生成列重新计算；新约束不满足时整单失败。
- [ ] 反向发布、原单已回滚标记、记录/表版本、历史和通知记录共同提交，原始记录不删除。
- [ ] 同原单的并发申请、响应丢失重试与重复执行不产生重复有效回滚；未发布申请取消后可重新申请。
- [ ] 回滚详情展示前后关联和冲突原因，输入和申请意图可恢复，无强制覆盖入口。

## 验收用例

主要负责：AC-041、AC-042、AC-043、AC-044。

## 验证证据

真实 MySQL 的单条/混合反向发布、后续修改、删除重建、新唯一约束、自动字段以及并发回滚；HTTP 与 Web 的申请回滚、重新审批、结果与历史关联。正向发布测试只作必要回归，不复制每条断言到额外层级。

## 临时结构与退出条件

无新临时结构。复用正式发布模型，不添加强制恢复 SQL、免审批回滚或旧接口。
