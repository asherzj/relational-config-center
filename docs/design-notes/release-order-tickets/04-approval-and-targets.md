# T4（#51）：提交审批并管理在途目标

状态：用户已确认；ready-for-agent。

## 父工单

Part of #48：管理台正式发布闭环规格。

## 要构建什么

申请人提交草稿后冻结内容并占用已知记录；其他审批人可查看差异、批准或拒绝，申请人/管理员可取消尚未发布单据。状态变化、目标占用和历史一致，拒绝后可复制为新草稿重新核对。

## 验收标准

- [ ] 提交时重验记录基线和规则，冻结服务器核实的内容/表结构/变更语义，提交后禁止修改。
- [ ] 已知目标的占用从提交开始，冲突零残留；拒绝/取消释放，等待没有自动到期释放。
- [ ] 有权限的另一人一次批准足够，ADMIN 也不得自批，批准/拒绝意见必填。
- [ ] 申请人与 ADMIN 按当前角色取消，非法动作和旧状态版本均有稳定拒绝结果。
- [ ] 拒绝单与意见保留，复制新草稿重新读数据并保留显式确认，不复制审批。
- [ ] 同键重复审批返回原业务结果；竞争批准/拒绝/取消至多一项生效，历史与状态一致。
- [ ] 先前合法审批不因审批人未来停用/撤权被自动作废，新动作仍按当前角色校验。

## 验收用例

主要负责：AC-018、AC-019、AC-020、AC-021、AC-022、AC-023、AC-024、AC-025。

## 验证证据

HTTP 身份、状态、意见和版本矩阵；真实 MySQL 的占用/审批竞争及拒绝/取消释放；审批、拒绝、复制与取消界面定向验收。成功发布释放占用由 T5（#52） 的 AC-026 独立负责，不以桩发布作为本单证据。
