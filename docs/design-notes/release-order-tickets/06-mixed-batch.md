# T6（#53）：交付单表最多 1,000 项混合批量发布

状态：用户已确认；ready-for-agent。

## 父工单

Part of #48：管理台正式发布闭环规格。

## 要构建什么

编辑者在一张草稿里组织同表多项 ADD/MODIFY/DELETE，能够逐项编辑、移除及勾选多行删除。审批人查看整单明细，发布者一次提交全部变更；任一项无效或冲突都不能留下半单结果。

## 验收标准

- [ ] 同表 1～1,000 项混合变更经正式草稿、审批和发布入口生效，删除所有临时单条上限。
- [ ] 数据页可加入本人已有同表草稿，草稿详情可添加/修改/移除明细，列表支持明确选择多行删除。
- [ ] 重复已知 id、跨表项、非法项及超出公开请求/事务预算整体拒绝并指出问题，已有草稿不部分覆盖。
- [ ] 批量提交取得全部已知目标占用，交叉目标竞争失败零残留；发布检查全部版本，任一失败整单回滚。
- [ ] 自增 id 新增返回每项实际 id，重试不重复新增；独立请求不依据内容相似合并，唯一约束由数据库裁决。
- [ ] 真实 1,000 项代表样本经过同一正式流程；按表成批读取最终行，结果与变更记录完整，不靠先提交部分明细后补记录。
- [ ] 首版不添加文件导入、跨表或隐式分批提交。

## 验收用例

主要负责：AC-037、AC-038、AC-039、AC-040。

## 验证证据

真实 MySQL 的 1,000 项完整样本、混合失败、重复身份、交叉竞争及自增/唯一约束；HTTP 边界和明细定位；Web 的加入草稿、批量删除及大单展示/审批/发布。性能证据只为证明批准的规模与预算，不添加任意 1,000 并发用户的额外承诺。
