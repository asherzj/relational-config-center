# T1（#49）：管理账号角色并落实全局授权

状态：用户已确认；ready-for-agent。

## 父工单

Part of #48：管理台正式发布闭环规格。

## 要构建什么

部署维护者可通过已有维护入口给指定账号授予首位 ADMIN，管理员可在管理台检索账号并组合分配全局角色；新老账号默认只读，角色变更约束原会话的后续请求。规则目录只有 ADMIN 可改。角色操作与现有账号维护互相一致，不产生丢失最后一个管理员的正常管理路径。

## 验收标准

- [ ] VIEWER、EDITOR、APPROVER、PUBLISHER、ADMIN 的全局能力按父规格执行；不能从注册顺序推断 ADMIN。
- [ ] 当前账号、登录会话和 CSRF 能力复用，普通用户不能伪造角色或修改控制表。
- [ ] 管理台提供所需账号列表、当前角色和角色分配；角色调整后旧会话无需重登，后续请求执行新权限。
- [ ] 角色变化保存永久身份、前后角色和时间，重复/并发管理请求有稳定结果。
- [ ] 维护命令与新老账号迁移有真实验证，最后管理员不变量及恢复方式可重复验证。
- [ ] 现有规则管理 UI/HTTP 按角色适配；过渡期间旧记录写入仅允许 EDITOR/ADMIN，不能给只读者保留后门。

## 验收用例

主要负责：AC-001、AC-002、AC-003、AC-004、AC-005、AC-006。

## 验证证据

HTTP 权限矩阵证明服务端授权；真实 MySQL/维护命令证明迁移、角色存储及并发约束；角色管理界面定向验收证明用户可以完成赋权。既有账号回归须适配默认只读，不能通过把测试账号自动设为 ADMIN 掩盖默认权限行为。

## 临时结构与退出条件

本工单保留的现有记录写 API 是既有功能过渡入口，只对具编辑权限者开放；T5（#52） 负责连同旧 Web 调用、脚本与验收调用一起删除/迁移。不得以本单结束声称已强制审批。
