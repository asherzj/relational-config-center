# 本地账号交付工单拆分（已确认）

父规格：[PM-009 规格：本地账号注册、登录、会话与真实 Operator #34](https://github.com/asherzj/relational-config-center/issues/34)。需求入口为 [#29](https://github.com/asherzj/relational-config-center/issues/29)。规格已发布且带 `ready-for-agent`；本拆分已由用户授权执行，交付工单为 #35–#40，均已回读核对正文、标签、父规格和原生阻塞关系。

每张工单使用独立分支/工作树完成实现、针对性验证、评审和交付周期，下一张从干净上下文读取完整工单。T1–T6 对应 GitHub #35–#40。每个工单启动一个独立 subagent，并自行完成验证、评审、commit 与 push；默认按依赖顺序执行。

## 1. T1：自行注册并使用本地账号登录

**阻塞于：**无。

**交付什么：**在独立账号入口完成注册→自动登录→显示当前身份，以及退出后凭用户名和密码再次登录。包含最终账号字段规范、安全密码保存、注册原子性、MySQL 会话基础、CSRF、注册/登录限速与防伪造；账号页面只消费统一当前身份能力。该切片可直接通过 Web 与 HTTP 演示，不把“建表”“后端”“前端”“测试”拆成各自独立工单。

**主要验收用例：**AC-002、AC-003、AC-004、AC-005、AC-006、AC-031。

**验收标准：**

- 新建受保护的最终账号及认证控制表，提供显式初始化/迁移；注册账号与初始会话一起成功或失败。
- 注册需要唯一用户名、唯一未验证邮箱和合规密码，显示名称可默认；字段比较和密码处理符合规格。
- Web 注册/登录入口展示真实当前身份，正常失败、占用冲突和限速可理解且不会自动重放提交。
- 登录前与登录后 CSRF、Cookie 属性、随机会话令牌和令牌摘要持久化从本切片起生效，不以明文密码或假身份搭建中间方案。
- 无效/到期/已撤销凭据不能取得账号入口的身份；未知用户名、错误密码和停用账号的登录响应一致。停用状态可由数据库测试前置准备，本切片不提前交付维护命令。
- 正常测试通过真实注册/登录建立会话；持有旧部署 Token 不能绕过新账号接口的认证。

**验证证据：**HTTP + 真实 MySQL 证明注册唯一性、原子性、密码校验、限速与凭据边界；Web 行为测试证明注册/登录反馈和当前身份呈现；字段复杂边界按需增加纯规则测试。

**临时结构与退出条件：**引入 TMP-01：开发期间旧业务工作区暂保留原部署认证，新账号切片仅在账号入口验收，不能宣称已经保护或归因整个业务管理台。T3 负责统一业务入口、迁移原有集成测试并删除旧 Token、固定 Operator 和免认证路径；T1–T2 不作为完整账号功能发布。不新增可长期选择旧身份的部署模式或身份 Registry。

## 2. T2：维护个人资料与跨设备会话

**阻塞于：**T1。

**交付什么：**用户在个人入口修改显示名称、凭密码修改邮箱/密码，查看当前身份并退出当前或全部设备；多设备会话、刷新/重开恢复、前台交互续期、后台不续期与绝对到期完整可用。

**主要验收用例：**AC-010、AC-011、AC-012、AC-018、AC-019。

**验收标准：**

- 活动接口仅记录活动信号与服务器时间；前台真实交互至多每 60 秒报告一次，后台请求不续期，失效会话不可续活。
- 会话 30 分钟闲置或 8 小时绝对期限到期，多设备并存且普通退出只影响当前会话；同浏览器标签页同步退出。
- 个人资料只能修改自己的显示名称和未验证邮箱；邮箱修改校验当前密码及数据库唯一性，不改变永久身份或会话期限。
- 改密、退出全部设备与会话撤销版本一起生效；旧会话失效，普通使用者没有账号列表或管理他人的接口。
- 为登录签发建立安全状态重检，不能把旧密码/旧撤销状态直接写入新会话；T5 主要负责包含维护命令在内的完整并发用例与证据。

**验证证据：**HTTP + MySQL 与可控时钟证明多会话、活动、到期、资料和撤销语义；Web 证明个人表单、活动报告、Cookie 恢复及标签通知。改密/全部退出同时提供 AC-013/AC-014 的部分证据，完整用例唯一主要责任在 T5。

**临时结构与退出条件：**不新增临时结构；TMP-01 继续由 T3 删除。此处的基础会话展示与清理作为最终组件保留，不用临时假登录页。

## 3. T3：切换业务入口和真实归因，删除旧认证

**阻塞于：**T2。

**交付什么：**用户必须登录才能进入既有管理工作区和调用业务 API；所有规则与配置写入归因当前账号，旧部署 Token 与免认证路径彻底退出。用户可看到真实身份，登录后安全返回原站内目标。

**主要验收用例：**AC-001、AC-007、AC-008、AC-009、AC-015、AC-021、AC-022、AC-023、AC-030。

**验收标准：**

- 全部业务 API 校验真实会话，全部状态变更校验 CSRF；原 Token 不再认证任何业务请求。健康接口保持公开，空账号库可进入注册。
- 将账号入口与工作区路由连接，清除代理注入 Token、免认证开关和固定 Operator 的正常运行路径，旧配置给出明确失败反馈。
- 配置行与三种规则目录均从当前请求取得永久 Account ID；并发账号不能通过共享服务字段串用身份。
- 扩展必要的实时字段兼容检查，拒绝装不下完整 ID 的操作人字段；历史值保留原文，业务结构不由 Admin 修改。
- 撤销之后尚未通过认证的请求拒绝；已认证的在途请求允许完成并归属原账号。保留规则、Schema、Auto Fill 与错误分类。
- 账号、会话、CSRF 和限速控制表不能被发现或通过通用管理接口读写。
- 同步迁移原有 HTTP/MySQL 集成测试的认证准备方式，通过真实注册登录取得身份；处理受旧配置移除影响的维护/迁移连接入口，不留无法启动的既有命令。

**验证证据：**HTTP + 真实 MySQL 证明全业务认证/CSRF、控制表拒绝、两账号并发归因、字段不兼容与撤销边界；Web 证明路由保护、安全返回和 403 不跳登录；原有业务回归证明规则行为仍然成立。

**临时结构与退出条件：**这是 TMP-01 的明确收缩/删除工单。完成时没有业务 Token/免认证后门、代理 Token 注入、正常请求固定 Operator、测试认证绕过或可切回旧身份的 Feature Flag。完成后仍需 T4–T6 验证完整规格再报告功能交付。

## 4. T4：会话中断时保留编辑意图并隔离账号数据

**阻塞于：**T3。

**交付什么：**用户编辑配置或规则期间会话过期，工作区遮住，同一账号重登可以恢复内存中的输入和 Change Set；不同账号、主动退出、刷新和迟到响应按规格清理。结果不确定时只提供查询确认，不自动重试写入。

**主要验收用例：**AC-016、AC-017、AC-026。

**验收标准：**

- 过期、普通撤销与服务故障分别处理，未验证身份前不得展示工作区；停用后清除可恢复草稿。
- 同账号重登后重新检查当前规则和目标数据，保留编辑意图但要求再次确认，不能自动提交。
- 主动退出、刷新、切换账号及跨标签事件清除相应内存；旧账号迟到响应不能重新填充新账号页面或查询缓存。
- 注册/改密/业务写响应丢失时不给出未经证明的成功或失败结论，不自动重放；支持重新登录或查询实际状态。
- 不把凭据、邮箱或配置草稿放入浏览器持久存储，不顺带实现配置乐观并发控制。

**验证证据：**Web 行为测试覆盖所有现有编辑流程的可观察状态；HTTP 故障注入证明“已提交但响应丢失”与恢复路径，复用 T1–T3 的数据库行为证据，避免在每层重复用例。

**临时结构与退出条件：**无。遮罩、重认证、内存草稿隔离和结果不确定提示均为最终行为。

## 5. T5：通过维护命令恢复、停用和修正账号

**阻塞于：**T2。

**交付什么：**部署维护者不依赖邮件或已登录 Web，通过受数据库权限保护的命令查找账号、重置密码、停用、恢复及更正邮箱；现有会话随安全状态变化失效，正常使用者没有这些命令的替代 Web/API 权限。

**主要验收用例：**AC-013、AC-014、AC-020。

**验收标准：**

- 隐藏终端输入或标准输入接受密码，不允许通过命令行参数或输出回显密码；校验与注册/改密一致。
- 重置密码与撤销全部会话一致提交；同密码重置仍撤销会话，恢复账号不复活旧会话。
- 邮箱更正保持唯一性和账号归属，不变更用户名/Account ID，不发邮件，不引入删除、合并或临时密码状态。
- 通过真实并发用例证明登录签发与改密、重置、停用、全部退出竞争时，不会补发基于旧状态的有效会话。
- 维护连接不依赖正常 Admin 的就绪状态，错误可诊断但不泄露敏感资料；文档明确停用账号不能作为人员封禁。

**验证证据：**启动真实维护命令，以 HTTP 验证旧会话/旧密码和恢复后的结果；真实 MySQL 并发测试覆盖所有安全状态变化与登录签发竞争。复用 T2 的个人改密/退出证据，补齐 AC-013/AC-014 全部场景。

**临时结构与退出条件：**无。维护工具是最终能力，不以直接手改数据库或临时脚本替代交付。

## 6. T6：验证存量升级与真实浏览器完整交付

**阻塞于：**T4、T5。T3 已通过 T4 间接满足，不重复声明传递依赖。

**交付什么：**部署者能按文档把存量实例一次切换到账号模式，正确配置同源 HTTPS/本机 HTTP 和脚本调用；缺结构会明确拒绝启动，正常重启恢复会话与限速。真实浏览器证明整个工作流，并核对全规格交付证据。

**主要验收用例：**AC-024、AC-025、AC-027、AC-028、AC-029。

**验收标准：**

- 验证 fresh 与既有部署升级后的认证控制结构和关键约束一致；包括维护连接、空账号启动、缺结构拒绝、数据库不可用和超时分类。
- 正常重启保留有效会话与限速，过期凭据不复活；清理/容量策略不影响有效状态。
- 交付维护窗口升级顺序、旧实例停用要求、HTTPS 代理示例、可信客户端 IP 配置及完整 Cookie/CSRF/活动脚本示例。
- 在正式 HTTPS 与显式本机 HTTP 配置下核验 Cookie 和敏感材料保护。
- 新增一条真实浏览器连接同源代理、Admin 和 MySQL 的注册→配置变更→真实归因→退出系统路径，接入可重复执行的验证入口。
- 汇总全部 31 条 AC 的交付与证据，确认 TMP-01 已删除，完成 Web 测试/类型检查/构建、Go 测试/构建和真实 MySQL 回归；最终同步领域/部署文档与 Notion 后报告功能完成，不自动关闭需求 #29 或父规格 #34。

**验证证据：**真实进程 + MySQL 的启动、迁移、重启和故障验证；一条浏览器系统关键路径；全量现有回归。不是把其他工单的测试留到最后：每个早期切片已各自实现并验证其行为，本工单独立证明实际部署和系统连接。

**临时结构与退出条件：**不新增临时结构；复核 TMP-01 的删除证据。功能交付后不留旧入口兼容、认证绕过或只能在开发环境成立的替代结构。
