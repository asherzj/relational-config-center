## 验收要求

| 编号 | 已确认要求 | 验证方式 |
| --- | --- | --- |
| AC-01 | 主导航为“统一变更入口 → 发布单”；统一入口的标题、草稿引导文案一致，现有路由及权限不变。 | 导航与页面测试；桌面、390px 手机实际跳转。 |
| AC-02 | 发布单业务标题是详情唯一主标题，状态紧邻；保留一次返回列表，不再重复发布单大标题及详情面包屑。 | DOM 标题层级、截图及返回操作。 |
| AC-03 | 申请人、创建时间、变更数紧凑展示。完整单号、版本、复制或重新准备来源在默认收起的基本信息中，单号与复制按钮相邻。 | 折叠展开、完整 ID、复制成功与失败反馈。 |
| AC-04 | 人员默认显示名称，无名称时显示账号短标识；按需展开完整 UUID 并复制。实际人员、时间继续来自已记录事件。 | 键盘展开、完整值复制与失败回退、现有阶段事件测试。 |
| AC-05 | 页头右侧放当前状态允许的操作，草稿包含编辑和提交。黑色留给当前主操作；取消草稿进入更多操作且危险呈现，仍先确认。其他生命周期动作保留权限、写入互斥、未确认请求与原键重放。 | 草稿、审批、发布、完结、回滚及恢复现有测试；更多菜单和取消确认浏览器操作。 |
| AC-06 | “添加变更”位于“变更内容”工具栏，使用次级按钮；进入统一入口并携带当前草稿和表，写入中禁用。 | 链接参数、当前草稿追加路径与禁用状态。 |
| AC-07 | 正向发布显示真实整单阶段及保存的逐表模板节点，当前节点突出；不以固定四阶段替代实例。取消、拒绝、回滚不得伪装成正常完结。原单回滚显示真实恢复发布节点，未发生的完结节点显示已终止，不推断完成或归因。 | 各生命周期阶段测试；桌面、手机截图及长人员名换行。 |
| AC-08 | 草稿仅显示“变更内容”，无单独申请切换按钮。实际发布结果存在时才显示“申请内容 / 实际发布结果”切换；恢复结果仅在有真实恢复执行时提供。筛选文案为“只显示有变化的字段”。 | 草稿及实际发布/回滚内容切换测试和浏览器操作。 |
| AC-09 | MODIFY 完整对比中，同值、同为 NULL、同为空串、未提交的字段均无红绿底色；实际变化仍以原值浅红、新值浅绿表达。自动填写/数据库生成保留待生成说明，不推断未来结果；新增和删除继续完整展示。 | 差异组件回归；真实申请中同值、NULL、未提交和变化字段的计算后背景色。 |

## 布局与交互

从上到下为紧凑页头（返回、业务标题与状态、当前操作、摘要和可展开基本信息）、真实整单阶段、逐表流程实例、变更内容、按状态显示的回滚原因、操作历史。宽屏页头信息与操作分区，窄屏自然换行；长 ID 在所属区域换行，字段表只在自身容器横向滚动。

保留加载、局部读取失败重试、姓名读取失败、空草稿禁用提交、权限限制、未知结果恢复及未保存保护。更多菜单保留在所属工作区，不能绕过会话失效遮罩。折叠与菜单支持键盘，危险确认默认聚焦取消。

本次改变展示和操作位置，不改变发布单状态机、申请内容、执行范围、版本、接口或路由。历史验收文档保留原时点文案。
