## 验收入口

主入口是独立迁移维护命令，连接真实 MySQL 8.4，观察退出码、状态、安全诊断和实际持久结果；现有 Admin 进程启动/HTTP 就绪检查、真实 Compose 只证明必要的系统接线。无前端页面变更。

## 交付工单

1. **T1：通过独立 Goose 命令初始化、升级并恢复控制结构。**
   - **阻塞于**：无，可立即开始。
   - **交付什么**：维护者可初始化新库、查询状态、向前升级；重复调用不重复变更；同库迁移互斥，失败或中断留有可诊断状态并要求显式恢复。普通升级拒绝静默接管已有结构。
   - **主要验收用例**：AC-001、AC-002、AC-003、AC-007、AC-008、AC-009、AC-010、AC-013。
   - **验证证据**：真实命令/MySQL 证明版本与结构、独立维护连接和恢复；双进程与中断证明互斥和结果未知处理。包含本工单相关回归。
   - **退出条件**：本工单迁移与恢复行为必须完整；暂留旧当前初始化入口，明确由 T3 删除。不把未确认结果当成功，不给旧库无校验接管路径。
   - [完整工单](goose-migration-tickets/01-migration-command.md)。

2. **T2：校验并接管当前存量数据库。**
   - **阻塞于**：T1，使用其锁、状态和显式维护入口。
   - **交付什么**：验证当前结构后登记基线，重复接管安全；不兼容及旧版本拒绝；按既有流程到达基线后可接管，已有账号、发布历史和记录版本保留。
   - **主要验收用例**：AC-004、AC-005、AC-006。
   - **验证证据**：真实结构差异与固定历史数据、账号/发布公开读取；代表性旧库经历史流程升级后接管。锁及状态能力复用 T1，不重复重建完整故障矩阵。
   - **退出条件**：无新的临时兼容层；接管不复用仅能查询表的弱 Ready 判定；历史命令和脚本保留明确旧库职责。
   - [完整工单](goose-migration-tickets/02-verified-baseline.md)。

3. **T3：统一部署入口并以迁移状态守住 Admin 就绪。**
   - **阻塞于**：T2；T1 为传递依赖。
   - **交付什么**：新库和已接管库统一先迁移、再加载本地 fixture、再启动 Admin；启动和就绪检查只读验证版本、状态与结构。迁移控制表受保护，删除旧当前初始化路径，更新文档和 CI。
   - **主要验收用例**：AC-011、AC-012、AC-014、AC-015。
   - **验证证据**：真实 Admin 启动/HTTP、真实镜像和隔离 Compose；新库/升级结构等价、历史迁移与 fixture 回归；入口引用检查证明旧路径已收缩。
   - **退出条件**：删除 T1 暂留的旧当前初始化入口、重复维护的当前结构和所有当前调用方；历史快照/脚本只保留旧库职责。无就绪绕过开关。汇总全部验收证据并更新 Notion 的实际交付范围。
   - [完整工单](goose-migration-tickets/03-deployment-readiness.md)。
