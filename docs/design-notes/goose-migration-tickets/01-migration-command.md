## 要构建什么

维护者可以通过独立命令查询状态、初始化新库和向前升级已接管库。成功的重复调用不会再次执行迁移；并发操作有界互斥，失败或中断可诊断并只能经维护者显式恢复。已有未接管结构明确拒绝普通升级，为下一工单的严格接管保留边界。

## 验收标准

- [x] AC-001、AC-002：新库及已知旧版本升级成功，新安装/升级结构一致，固定历史数据保持不变，不加载开发 fixture。
- [x] AC-003：只读查询不创建账本；重复升级不重复变更；未接管存量库不被静默接管。
- [x] AC-007：连接不可用、超时和权限不足有界失败，诊断不泄露凭据及业务数据，不冒充成功。
- [x] AC-008：两个独立进程对同库初始化、升级或恢复互斥；锁等待超时退出，不破坏持锁者结果。
- [x] AC-009：真实部分 DDL 成功、中断及保存成功版本后的未确认窗口均可辨认，普通升级拒绝自动恢复未知结果。
- [x] AC-010：维护者可在核查后显式恢复，条件不满足时仍拒绝；无 down、reset、强制标成功或清历史入口。
- [x] AC-013：维护入口只依赖数据库维护配置，Admin 无法就绪时仍可工作；既有维护命令和权限职责保持。

## 验证证据

真实 MySQL 8.4 和公开维护命令验证实际结构、版本与退出结果；两份测试发行证明后续升级，不能靠新增无意义生产字段制造验收。双进程与系统边界中断证明锁及恢复；独立维护连接、Go 完整测试和相关现有回归必须通过。失败日志保留并在修复后重新执行对应检查。

## 临时结构与退出条件

旧当前初始化 SQL 暂留以保持未切换调用方可运行；T3 负责切换全部当前调用方并删除该入口及重复定义。本工单的新命令本身必须可完整独立使用，不得以恢复桩、空操作或“后续再验证”结案。
