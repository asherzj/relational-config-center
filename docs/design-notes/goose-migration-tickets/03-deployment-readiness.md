# T3：统一部署入口并以迁移状态守住 Admin 就绪

## 父工单

Part of #67：https://github.com/asherzj/relational-config-center/issues/67

状态：用户已确认，ready-for-agent。

## 要构建什么

部署者使用构建产物运行独立迁移任务，新安装和后续升级统一走 Goose。Admin 启动及就绪检查只读判断版本、迁移状态和结构；本地 Compose 串联迁移、fixture 与 Admin，失败时阻止后续启动。删除旧当前初始化路径，保留有明确职责的历史迁移和快照，完成开发/部署说明及验收证据。

## 验收标准

- [ ] AC-011：未接管、落后、未知/超前版本、失败未确认、结构损坏均拒绝启动/就绪；正确状态通过；业务进程不改表或登记版本，恢复后就绪可通过。
- [ ] AC-012：迁移与恢复控制结构受 RCC 控制表规则保护，通用接口不能发现为业务表、绑定或访问它们；正常业务表不受影响。
- [ ] AC-014：真实镜像和 Compose 对新库、已接管卷、未接管卷、未确认卷执行正确顺序和失败阻断；存量接管必须显式执行。
- [ ] AC-015：当前新安装和升级只有 Goose 一个结构来源；全部当前调用方切换，旧当前初始化入口及重复定义真实删除。
- [ ] 历史 SQL/快照只保留旧库升级及测试职责，开发 fixture 保持独立且不进入生产迁移。
- [ ] 新命令纳入构建与 CI；当前文档、历史升级说明、恢复步骤和新增迁移约定一致。
- [ ] 汇总 AC-001～AC-015 的交付证据、收缩结果及架构文档；完成后更新 Notion PM-050 的实际迁移交付范围，保留其他工作真实状态。

## 验收用例

主要交付 AC-011、AC-012、AC-014、AC-015。完整 Given/When/Then 沿用父规格；T1/T2 的验收证据保留，最终收尾只补跨工单接线和回归，不替代各工单的独立验证。

## 验证证据

真实外部 Admin 进程和 HTTP 就绪状态证明只读门禁；真实镜像及隔离 Compose 证明部署顺序与失败阻断。新安装/升级等价、旧库迁移、账号/发布和 fixture 相关真实 MySQL 回归证明兼容。引用和构建检查证明无当前旧初始化调用方；Go 完整测试及必要 CI 检查通过，无前端改版或测试专用业务入口。

## 临时结构与退出条件

负责删除 T1 引入的新旧当前初始化并存：迁移全部当前调用方，移除旧入口和重复维护的当前结构；只允许冻结旧库测试快照及历史升级脚本保留其明确用途。不留下就绪绕过开关、静默接管或长期备用新安装通路。证据与 Notion 同步后才能报告完整功能完成。
