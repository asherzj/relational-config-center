# 本地账号注册、登录与会话：澄清记录

本记录承接 `flow-feature` 的需求澄清阶段。Q1–Q20 均已确认，详细参数和验收基线见[已确认参数与验收基线](./local-account-acceptance-draft.md)。完整规格已发布为 [GitHub #34](https://github.com/asherzj/relational-config-center/issues/34)，[交付工单拆分](./local-account-ticket-plan.md)已确认并发布为 #35–#40；不表示功能已实现。

## 来源与现状

- 关联需求：[GitHub #29](https://github.com/asherzj/relational-config-center/issues/29)。开始澄清时包含企业身份替换等更大范围；发布前复核时已更新为“实现本地账号注册、登录与会话及真实 Operator 归因”，企业身份、完整角色和持久审计另行推进。本轮创建独立详细规格关联它，不改写或自动关闭原需求。
- 项目计划：[Notion 项目管理总表](https://app.notion.com/p/3ca8544cc98980559f27e17f2c94cbaf)。本轮对应 PM-009，并增加本地账号注册；第二轮确认将 PM-012 中现有字段的真实 Operator 归因提前纳入本轮。PM-010 身份接入、PM-011 角色授权及 PM-012 的持久审计仍按后续工作包推进。
- 当前 Admin 只校验部署级 Bearer Token；Web 的同源代理注入共享 Token，没有终端用户账号或登录会话。
- 当前所有访问者使用同一套规则和数据操作能力；Mutation Policy 约束表允许执行的操作，不区分使用者。
- 当前 Operator 来自部署配置。配置行变更与规则目录写入分别取得这个固定值，不能把登录成功等同于真实操作人已落入审计字段。
- 旧行为边界见 [ADR-0003](../adr/0003-single-tenant-trusted-network-first-iteration.md)，本轮范围决策见 [ADR-0017](../adr/0017-introduce-local-accounts-in-the-trusted-network.md)。

## 第一轮：已确认（2026-09-07）

1. **账号与部署边界**：本地账号指系统内建账号，由本系统管理账号和密码；继续面向单组织、本机或可信内网。
2. **本轮范围**：注册、登录、登出、会话恢复、过期、撤销、未登录访问保护和登录后安全返回原目标；保留统一的当前身份接口。企业身份接入、角色授权与持久审计按后续工作包推进。
3. **注册准入**：允许自行注册，不采用邀请作为注册前提。注册后的启用与访问能力在第二轮确认。

## 第二轮：已确认（2026-09-07）

用户接受 Q4–Q8 的推荐方案，并对 Q5 增加“要求邮箱，但是暂时不做任何邮件操作”的约束。

4. **注册后能力**：注册成功即启用，拥有现有管理能力，并继续受表规则约束。所有已启用账号能力相同；能够访问注册入口的人可以自行成为管理台使用者。这里的启用不等同于已确认注册后自动登录。
5. **账号资料**：原推荐以唯一用户名和密码登录，另设可修改的显示名称、不可修改的用户名和永久内部 ID；用户要求填写邮箱。本轮不执行邮件验证、通知、找回或其他邮件操作；邮箱的登录用途、唯一性、修改与未验证状态在第三轮确认。
6. **真实 Operator**：本轮把配置行与规则目录写入的创建人、修改人切换为当前已认证账号的稳定 Account ID；界面按需显示名称，既有固定 Operator 值保留原样。持久审计仍属于后续工作包。
7. **旧认证迁移**：业务接口统一要求用户会话，同次移除代理注入共享 Token 和免认证开关；健康检查继续无认证。原有脚本调用必须迁移，不保留共享 Token 作为业务 API 的后门。
8. **会话体验**：服务端保存会话，浏览器使用安全 Cookie；允许多设备并行，刷新或重开浏览器可恢复未过期会话。闲置 30 分钟或登录满 8 小时失效；普通退出只撤销当前会话，另提供“退出全部设备”。时长是本项目已选择的业务参数，不是通用强制标准。

## 第三轮：已确认（2026-09-07）

用户接受 Q9–Q15 的全部推荐方案。

9. **邮箱语义**：邮箱必填、唯一，仅作未验证资料；仍使用用户名登录。输入当前密码后可以修改邮箱，不能凭邮箱找回、合并账号或证明身份。
10. **注册成功与重复注册**：注册成功后自动登录，安全返回原访问页面；没有原目标时进入默认首页。重复注册明确提示用户名或邮箱已占用。
11. **账号维护与恢复**：用户凭当前密码改密，成功后撤销全部设备会话。忘记密码由部署维护者通过服务器命令重置；工具还支持停用与恢复账号，停用立即撤销全部会话。本轮不提供账号删除，不让普通使用者管理他人账号。
12. **闲置与未提交内容**：前台实际交互计入活动，后台自动请求不续期。过期后遮住工作区，未提交内容仅保存在页面内存；同一账号重新登录可以继续，换账号、主动退出或刷新页面则清除。恢复后不得自动提交。
13. **会话持久化与故障**：会话存放于 MySQL，正常重启后仍可恢复未过期会话。数据库不可用时明确提示服务暂不可用；恢复后重新验证会话，不自动重放写操作。
14. **安全基线**：密码 15–128 个字符，允许空格，不强制字符组合，只保存安全密码哈希；加入登录与注册限速及 CSRF 防护。正式内网访问使用 HTTPS，仅本机开发允许 HTTP。
15. **操作人字段兼容**：账号使用固定格式的永久 ID。操作人字段无法完整保存时拒绝写入并明确指出原因，由表维护者调整结构；禁止截断或回退固定操作人。历史值保留原文，不自动推断对应账号。

这些结论补充并细化前两轮；会话撤销与在途请求、维护命令细节、字段规范和升级验收在第四轮确认。

## 第四轮：已确认（2026-09-07）

用户接受 Q16–Q20 的全部推荐方案，并接受参数与验收草案中的详细内容。

16. **字段规范**：Account ID 为小写、含连字符的 UUID v4，固定 36 字符且不复用；用户名 3–32 个 ASCII 字符、按已确认字符集去两端空白并转小写；邮箱最多 254 个 ASCII 字符，大小写不敏感但不合并点号或 `+tag`；显示名称可省略，默认用户名，其余细节按已确认基线。
17. **维护与停用边界**：停用只针对账号，不承诺人员封禁；开放注册仍允许以其他资料注册。维护者可通过数据库权限工具查找、重置、停用、恢复或更正邮箱，不能删除/合并或变更 Account ID/用户名。接受隐藏密码输入、不发邮件、不增加临时密码流程，以及基线中的撤销/恢复/资料修改语义。
18. **并发与不确定结果**：注册与初始会话原子建立；唯一冲突最多一个成功。撤销后旧认证过程不能补发有效会话；已经通过认证的业务请求可完成并归因原账号。接受活动上报、多标签页与迟到响应隔离、稳定错误和不自动重放写入的完整约定。
19. **安全和升级**：接受基线中的 Argon2id、Cookie/CSRF、数据库限速、公开地址与代理信任、脚本调用和日志约束。以维护窗口停旧入口、迁移并验证新版；缺结构拒绝启动、空账号库可启动；不承诺无停机升级。
20. **验收冻结**：接受 AC-001–AC-031；公开 HTTP + 真实 MySQL 为主要入口，补充真实进程/维护命令、Web 状态和一条真实浏览器系统路径。允许发布独立规格关联 #29，然后展示工单拆分。

## 第二轮之后核实的实现约束

- 操作人 Auto Fill 当前只允许文本目标列，但实时字段信息没有字符容量或枚举集合；短 `varchar` 和受限 `enum` 仍可能通过现有规则检查，新的稳定 ID 不一定能够写入。Admin 不拥有业务表结构，不能自动扩列来绕过这个问题。
- 既有操作人字段只有字符串，没有身份来源标记；不能把历史文本自动归属给新账号。
- Web 无后台定时轮询，已禁用窗口聚焦重新查询，但挂载、网络重连和写入后的查询刷新可能产生自动请求。必须明确哪些请求计入会话活动，避免把后台请求等同于用户正在操作。
- 未保存表单和 Change Set 仅保存在当前页面组件内存中；页面刷新或因登录跳转而卸载会丢失输入。会话过期后的恢复方案是本轮要明确的新行为。
- 当前本地 Web 和 Admin 使用 HTTP，仓库没有随附 HTTPS 代理；内网正式部署的 HTTPS 与本机开发例外需要明确配置边界。
- 可复用的验收入口包括真实 MySQL 8.4 下的 Admin HTTP/进程测试，以及 Web 的 Vitest/jsdom 行为测试；目前没有浏览器端到端测试入口。移除免认证时需要同时迁移集成测试的认证准备方式。
